# 手动排班预览与访客审计去重设计

## 背景与目标

小米 14 对体验版 `.190@eacfd752` 的实测暴露了四个后续问题：删除已保存排班模板返回
“请求数据不符合要求”；草稿预览只显示本次生成的排班，无法与已有排班对照；紧凑月历中的日期、
节假日标识和排班文字在窄单元格内重叠；一次进入访客页会在同一分钟产生多条访问记录。

本批在不改变手动排班模板、草稿、发布流程和访客权限的前提下修复上述问题，并完成必要的服务端
部署、体验版上传与只追加放行。预览中不增加“已有 / 本次草稿”图例：已有排班使用嫩灰色，
本次草稿继续使用班种彩色和现有强调色，直接以颜色区分。

## 已确认根因与回归引入点

- 模板删除客户端在 `eacfd752` 新增 DELETE 封装时没有发送请求体；小程序请求桥因此省略 `data`，
  严格 JSON 请求校验把空 DELETE 判为不合法。仓库内可工作的同类 DELETE 会显式发送 `{}`。
- 编辑阶段预览已经读取开始月、结束月及相邻月份的现有日历并调用合并模型；创建草稿后的
  “草稿预览”只把草稿 assignments 传入同一月历组件，没有加载或合并现有日历。
- 共享日历单元格的节假日胶囊按普通月历尺寸设计；紧凑预览仍使用 16px 高、最多 28px 宽的胶囊，
  在七列窄格和较大系统字号下会侵入日期及排班文字区域。
- 访客页一次进入会先读取当前月，再预取前后各两个月；每个
  `POST /guest/groups/:groupId/calendar/read` 都独立插入审计记录，前台重读当前月还会再次插入。
  `79438d7b`/`325f82ea` 的五个月窗口读取使一次页面访问稳定放大为多条审计记录。

这些修改都不是语义等价重构，必须先增加旧代码失败、新代码通过的回归测试。

## 范围

### 纳入

- 修复已保存模板删除，不改变软删除、二次确认和删除当前/非当前模板后的页面行为。
- 草稿预览叠加同岗位的已有排班；已有排班嫩灰，本次草稿彩色，不增加图例。
- 仅调整紧凑预览月历的节假日标识、日期行和排班行占位，避免重叠。
- 将访客审计口径改为“每次进入访客页面一条”：同一页面实例内的预取、切月、前台恢复和重试
  不新增记录；退出后重新进入产生新记录。
- 更新严格契约、客户端封装、服务端原子去重、Mini 页面会话和生成解码器。
- 按服务端先部署、体验版后上传的顺序交付，并只追加新体验版到版本放行列表。

### 不纳入

- 不重命名模板，不改变 30 天周期、20 人、600 格、366 天应用范围或草稿发布流程。
- 不改变普通工作台、补录页或其他日历的默认颜色、字号、节假日标识和交互。
- 不删除或合并既有历史访客记录，不改变 90 天保留和月度匿名聚合规则。
- 不新增数据库表、列、索引或迁移，不记录手机号、visitorKey、登录码等额外敏感信息。
- 不提交审核，不正式发布，不把模拟器证据描述为小米 14 原生验收。

## 设计

### 1. 模板删除请求

`client-core` 的模板删除封装沿用既有 DELETE 路由，只显式提供返回空对象的请求体工厂，使小程序桥
稳定发送 JSON `{}`。服务端路由、权限、版本校验、软删除和响应形状均不变。

回归测试必须覆盖到传输边界：断言方法、URL 和实际请求体，而不是只断言上层函数被调用。接口失败
继续保留当前编辑快照和可重试状态，不把删除失败伪装为成功。

### 2. 草稿预览中的已有排班

草稿预览使用独立于编辑阶段预览的上下文缓存。打开草稿预览时先用当前业务月完成弹窗展示，再读取
该月及前后各一月的日历；用户左右切月时只补读尚未缓存的三月窗口。所有异步结果同时校验页面加载
序号和当前草稿身份，迟到结果不得写入已经关闭或切换的预览。

合并规则复用现有 `mergePreviewAssignments`：

- 只合并与草稿 `scheduleRoleId` 相同的已有排班，避免把其他岗位混入对照。
- 本次草稿保持班种原色和现有 added 强调；已有未被替换排班使用嫩灰底、灰色边框和柔和文字。
- 同一日期、同一岗位格被本次草稿替换时，原排班仍以嫩灰删除态保留，本次草稿彩色显示，方便逐项
  对照；不新增“已有 / 本次草稿”图例、文字标签或额外弹层。
- 颜色差异只作用于这个对照预览。通过预览专用的展示 tone/class 传入共享单元格，不把普通工作台
  和补录页的 `normal` 状态全局改成灰色。

如果已有日历读取失败，保留本次草稿内容并在弹窗内显示可重试错误；不得把“仅草稿可见”默认为
完整对照。长达 366 天的草稿不一次读取全部月份，避免扩大首开网络和内存成本。

### 3. 紧凑月历排版

只在 `calendar-cell.is-compact` 范围缩小节假日胶囊的高度、内边距、最大宽度和字号，并给日期行与
排班行保留稳定的垂直间距。普通月历继续使用现有尺寸和视觉。

两字节假日名称必须单行截断且不覆盖日期；“班”标识沿用同一紧凑尺寸。390px、320px 和系统大字号
下，日期、节假日和首条排班必须各自可辨，月历仍保持七列，不通过放大单元格或增加横向滚动规避。

### 4. 访客页面会话去重

严格请求契约给 `VisitorCalendarReadRequest` 增加可选 UUID `visitId`；响应契约不加字段。Mini 在
`onLoad` 为页面实例创建一个 UUID，并在该实例的所有月份读取中复用；`onUnload` 后该值失效，重新
进入页面创建新 UUID。切月、预取、前台恢复和网络重试不重建该值。

服务端在 `visitId` 存在时以 `groupId + visitId` 生成稳定的 UUID 主键，并执行“冲突即忽略”的原子
插入。这样五个月并发预取和重复请求只能成功插入一条，不依赖进程内缓存，也适用于多实例部署。
当前月读取先于后台预取，因此该条记录的 `businessMonth` 表示进入页面时的活动月份；首次插入保存的
请求 ID、OpenID、客户端上下文和 IP 保持现有隐私边界，后续同会话请求不覆盖它。

未携带 `visitId` 的旧正式版继续生成随机日志 ID 并按请求记录，避免服务端上线时破坏旧客户端。
稳定 ID 只用于数据库主键，不在日志或响应中暴露 `visitId`，也不建立可跨群关联的原始会话标识。

## 数据流与兼容顺序

1. 服务端先上线可选 `visitId` 契约和幂等插入；旧客户端请求仍可用。
2. 管理员删除模板时，Mini 明确发送 `{}`，现有软删除路由正常执行。
3. 管理员打开草稿预览时，弹窗先显示本次草稿，再按可见月份加载并合并已有排班。
4. 访客进入页面时生成一个 `visitId`；当前月和预取月份携带同一值，服务端只保留首次写入。
5. 服务端验证完成后再上传新体验版并只追加放行，保留旧体验版，不提审、不正式发布。

此顺序避免新版 Mini 先于服务端上线而被严格旧契约拒绝。模板删除和草稿预览的旧服务端响应形状
不变；新增请求字段只在新服务端生效。

## 测试与验收

### 自动化

- 删除：旧封装红灯证明 DELETE 无请求体；修复后断言 `{}` 到达传输层，并覆盖确认、取消、删除当前/
  非当前模板及失败重试。
- 草稿对照：红灯证明草稿预览未读取现有日历；修复后覆盖初始三月窗口、切月懒加载、同岗位过滤、
  未替换灰色、被替换灰色删除态、本次草稿彩色、迟到请求隔离和读取失败提示。
- 紧凑月历：契约测试锁定 compact 专属尺寸和非 compact 不变；检查 390px、320px、大字号、五/六行月、
  节假日与多条排班。视觉检查不新增图例。
- 访客：契约严格性、UUID 校验、Mini 页面实例复用、重新进入换 ID；API MySQL 集成覆盖五个月并发只写
  一条、重复/重试只写一条、重新进入写第二条、不同群不互相去重、旧客户端仍按请求写入。
- 运行 contracts、生成器、client-core、API MySQL 集成、Mini 定向与全量、typecheck、format/lint/build、
  包体、确定性、`pnpm smoke:browser` 和 `pnpm smoke:check-core`。

### 开发者工具与小米 14

- 开发者工具验证删除成功、草稿弹窗左右切月、已有嫩灰/草稿彩色、无图例、节假日不重叠及 Console/
  Network 无新增错误；模拟器证据单独标注。
- 上传的新体验版绑定最终干净 SHA、不可变版本、Manifest 和 receipt；只追加 allowlist，并验证上一版
  仍为 200、未知版为 426。
- 小米 14 后续验收必须使用该新体验版：删除模板不报错；草稿对照色清晰且无图例；月历日期、节假日
  和排班不重叠；一次进入访客页只新增一条记录。取得证据前保持“待真机复核”。

## 生产与回滚

访客去重涉及 API/contract，生产部署前重新读取现场 release，生成加密备份并校验登记、物理文件和
SHA-256；部署推送 checkpoint 后运行 schema、健康、权限、旧客户端兼容和完整 ECS verifier。无迁移，
schema 版本不应变化。

回滚应用 release 即恢复旧审计写入；新 Mini 若仍发送 `visitId`，旧严格服务端会拒绝该字段，因此回滚
时还必须从 allowlist 撤下仅依赖新字段的新体验版，旧体验版继续可用。正常交付只追加放行，不删除
历史版本。历史重复访客记录保持原样，不做生产数据清理。

## 完成标准

- 四个根因均有旧代码失败、新代码通过的回归用例。
- 已保存模板可删除；草稿预览能按可见月份对照已有排班，嫩灰/彩色足以区分且没有图例。
- 紧凑月历在目标宽度和大字号下无文字重叠，普通月历视觉不变。
- 同一访客页面实例在并发预取、切月、前台恢复和重试下只产生一条审计记录，重新进入产生新记录。
- Git checkpoint 推送、必要生产部署、体验版上传和只追加放行全部验证通过；未提审、未正式发布。
