# 小程序通讯录半屏筛选与性能诊断设计

## 范围

阶段 A 只实现两项：把通讯录筛选改成按真实窗口计算的底部半屏 Sheet；在现有“更多 → 测试工具”增加有界、脱敏、可复制的通讯录搜索诊断。阶段 B 必须等待匹配构建的小米 14 体验版数据，再判断瓶颈位于请求前、网络、服务端、结果转换或渲染，并且一次只处理数据支持的瓶颈。

本轮不修改正式 API contract、数据库、索引、生产部署方式、搜索排序、筛选语义、分页、权限或缓存隔离，不下载完整通讯录到小程序，也不扩展为无上限历史缓存。

## 半屏 Sheet

弹层外层高度只使用当前 `windowHeight` 的 50%，输出为运行时 px 样式；底部安全区只作为滚动内容内部 padding，不再参与外层高度计算。横竖屏变化通过成对注册/注销的窗口 resize 回调重新计算。CSS 不保留 `92vh/840px` 的近全屏上限。

现有 28px 顶部横条 WXS 手势、标题、“完成”、固定“清除全部筛选”、唯一纵向 `scroll-view`、筛选状态和滚动恢复全部保留。固定区域继续 `flex: none`；滚动区继续 `min-height: 0; flex: 1`；最后一项由滚动内容底部安全区 padding 保护。列表内部不绑定下滑关闭手势。

## 诊断边界

`develop/trial` App 只保留普通定长会话槽，最多 20 条通讯录搜索记录，默认停止；报告格式化、历史展示和复制只在 diagnostics 分包。测试工具还可设置一次性的“下次 App 启动首次搜索诊断”：持久化值只有 schema/armedAt/expiresAt，新 `App.onLaunch` 立即消费，`onShow` 恢复不消费，`release` 清除且不启用。请求 profile 只在记录开关开启时请求，基础库不返回 profile 时明确记录“不支持”。

每条记录保存确认时间和相对确认时间的阶段毫秒：App 启动、通讯录页面加载、事件开始、账号/群组/权限等待、facets/发布能力复核、真正发请求、收到响应、响应解码、卡片生成、`setData` 次数/估算字节、数据提交完成、下一渲染周期完成和总耗时。`JSON.stringify` 估算只在诊断开启时执行，其耗时单列，不混入卡片生成。网络记录从统一请求层读取非敏感 `x-request-id`，并在支持时换算 DNS、建连、TLS、首字节和下载阶段；回调/nextTick 不表述为用户已看到结果。

上下文只保存启动来源/warm resume、模式、页面会话序号、完成结果复用、进行中请求复用、重复拦截、是否带筛选、搜索词长度和粗分类、返回条数、下一页、响应估算大小、facets/发布批次就绪、网络白名单数值和随机诊断序号。任何记录和复制文本都不得包含原始搜索词、姓名、号码、完整工号、账号、群组、权限指纹、筛选值或游标。记录、单条序列化值、复制文本、Header 值和 request ID 均使用固定硬上限。

## 已确认的低风险等待

纯关键词搜索当前不会等待 facets。Client Core transport 与底层请求执行器仍保留能力门禁；通讯录 controller 在调用同一受保护 transport 前的第三次能力等待属于明确冗余，本轮只移除这一层。该改动不减少安全检查、不改变错误映射，也不声称已有手机性能提升。

## 验收

自动验证覆盖动态高度、安全区、横竖屏、监听器清理、固定头部/单滚动区、滚动恢复、诊断开关与上限、隐私清洗、复制结构、完成/进行中复用标记、请求 profile 和 request ID。随后运行 Mini 全量、类型检查、生产构建、source/verify/package/performance/determinism/CI dry-run、任务 lint/format 与核心 smoke。

小米 14 体验版按首次、相同条件第二次、不同关键词、带筛选、科室模式，以及条件允许时 Wi-Fi/移动网络执行。主要场景尽量各 5 次；报告只写真实中位数、最慢一次和阶段数据，未获得的数据标为“待小米 14 体验版实测”。
