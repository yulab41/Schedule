# 设计：微信小程序重制——以 Web 最新版为基准的全量移植（含平台运维控制台）

- 日期：2026-08-08
- 状态：用户已确认方向（重写小程序、以 Web 最新版为唯一功能基准、允许移动端交互重设计、平台运维控制台搬入小程序、目标是可弃用 Web 只保留小程序）
- 取代：`2026-08-08-wechat-miniprogram-design.md` 中与“小程序客户端页面功能”相关的内容；其微信登录/邀请/访客扫码/订阅消息部分继续有效。旧实施计划任务 13 的“轮值顺序/轮值规则、自动生成/保存生成”内容作废。

## 1. 背景与问题

现状：小程序任务 1–13 依据 2026-08-01 旧版 Web 设计编写，而 Web 已在轮次 45 起演进为“手动排班绘制 + 模板应用 + 草稿/发布/撤回”，并新增排班补录、导出、完整统计、紧凑排班配置（无轮值）。小程序因此出现：

- 多余：轮值顺序/轮值规则编辑、自动生成/保存生成入口；
- 缺失：排班补录、导出、成员联系方式编辑确认、统计按岗位/班种明细与计值班次、日历节假日标签、版本冲突处理、手动排班绘制式交互；
- 平台运维控制台（任务/备份/用户状态/节假日导入/群组恢复）在 Web 中只有 API、无界面，小程序也未提供。

结论：小程序应重写为“当前 Web 最新版的功能面 + 微信扩展”，而不是旧计划的独立实现。

## 2. 移植原则

1. **内核同一套**：业务内核 = `apps/api` + `packages/contracts` + `packages/database` + `packages/scheduling-domain`。小程序只做表现层与微信能力适配，不复制后端/领域逻辑（工作流冲突、统计计算、日期边界、迁移、审计全部复用现有实现）。
2. **前端行为等价移植**：Web 前端 `features/*-logic.ts`、`utils/*` 中的行为（日历绘制、手动模板编辑、草稿批次、版本月份分组、导出文件名、统计格式化等）以“同数据、同校验、同文案口径”移植为小程序 TS 工具/组件，并配套等价单元测试。
3. **允许移动端交互重设计**：点选绘制、滑动切月、长按、动画、手势、底部标签等可按小程序特性设计；但每次操作调用的接口、请求参数、错误提示、确认步骤必须与 Web 一致。
4. **不移植**：Vue/TDesign 桌面组件、hover/宽表格、PWA 离线缓存、浏览器推送、桌面布局；轮值/自动生成前端模块；免登录公开访客目录（微信设计已取消）。
5. **微信扩展保留**：微信登录与会话、邀请链接身份绑定、访客扫码（visitor key + 群码）、订阅消息（仅值班提醒）、群组小程序码，作为 Web 欠缺部分的补充。

## 3. 信息架构

### 3.1 底部标签（tabBar）

- 工作台：模块 Hub（见 3.2），对应 Web `HomeView` 工作台；
- 日历：月/周/列表三视图（含访客角色简化日历）；
- 通知：通知列表 + 提醒设置入口；
- 我的：微信用户资料（真实姓名）、联系方式、注销/退出登录（对应现有 `/users/me/deregister` 能力）。

### 3.2 工作台模块（与 Web `workbench-nav` 对齐）

| Web 模块 | 权限（与 Web 一致） | 小程序实现 |
| --- | --- | --- |
| 排班日历 | 所有角色 | 复用现有日历三视图 + 补节假日标签 |
| 群组管理 | 所有角色 | 复用现有群管理 + 目录/访客加入/退出/改名/改码/访客 key/解散恢复/转让 |
| 手动排班 | 群主/管理员 | **重写**为绘制式网格 + 模板 + 草稿批次 + 发布记录 |
| 排班补录 | 群主/管理员 | **新增**（既往月份绘制 + 待确认 + 补录记录） |
| 请假 | 所有角色 | 复用现有（创建/我的申请/审批） |
| 换班 | 所有角色 | 复用现有 |
| 加扣班 | 所有角色 | 复用现有 |
| 事件 | 群主/管理员 | 复用现有（时间线 + 访客访问记录） |
| 通知 | 所有角色 | 复用现有 |
| 统计 | 所有角色 | **补齐**汇总卡/成员表/按岗位/按班种/计值班次/原实对照/重算校验 |
| 成员 | 所有角色 | **补齐**联系方式编辑确认；保留角色/名单/转让/删除/邀请 |

## 4. 模块移植矩阵与关键行为

### 4.1 日历

- 月/周/列表三视图、周末红、今天金黄、班次色块、换替加角标、值班详情（电话）、节假日/调休标签；
- 访客（未登录扫码）与登录访客走 `guest-calendar`，成员走 `calendar`；
- 行为对齐：Web 轮次 58–61 的“开放当日换班/加扣班、周末樱桃红、今天黄、六/日列名红色”等日历表现。

### 4.2 手动排班（重写，复杂度最高）

对齐 Web `ManualScheduleView` + `manual-schedule-logic`：

- 模板编辑器：选择岗位 → 勾选成员 → 起始日期/循环天数 → 班种绘制（选中班种后点格子填/清除）→ 行/列/格子清除 → 撤销栈 → 失效标记（成员失效、班种停用/配置版本变更）；
- 模板：新建/编辑/删除/应用；应用前预览（冲突/空缺/连续值班）；应用起始日期自动取已发布排班之后的首个未排日期（`getNextAvailableStartDate`）；
- 草稿批次：按 `operationId` 分组，显示起止范围/角色/月份 chips，支持“发布整个排班”“删除草稿”；
- 发布记录：按 月份+岗位 分组，当前已发布/既往锁定/已归档三种状态；已过月份显示“排班补录”入口；归档版本可重新发布、删除；
- 发布/撤销/重新发布前的变更影响预览（工作流撤销、硬冲突、空缺、已过日期）与确认勾选，与 Web 完全一致；
- 版本冲突（409）时弹出 DataConflict 风格提示并刷新（小程序用对话框/半屏组件实现等价交互）。

### 4.3 排班补录（新增）

对齐 Web `PastScheduleView`：

- 岗位/月份切换；班种 + 成员调色板（点选保持选中）；点击既往日期加入“待确认”列表；再次点击移除；清空草稿；补录说明；确认后逐条调用 `createPastScheduleAssignment` 并显示“最近补录记录”；
- 未来日期不可补录（灰色）；已过月份自动锁定。

### 4.4 排班配置（重写）

- 仅保留“班种（增改删/启用/跨日/计入统计/颜色/时间）”与“排班岗位（新增/删除/参与成员勾选）”；
- **不提供**轮值顺序、轮值规则、自动生成/保存生成入口；
- 后端保留的轮值接口继续存在，但小程序不暴露（与 Web 一致）。

### 4.5 统计（补齐）

- 汇总卡：计划/实际/计值班次/周末/节假日/换班/加班/扣班/净值/请假补位/人工调整；
- 成员表：按实际次数排序，含计值班次/原实对照条数；
- 按岗位、按班种两个明细表；
- 刷新快照、重算校验（不一致摘要文案与 Web `summarizeRecalculateMismatches` 一致）。

### 4.6 成员与联系方式（补齐）

- 成员列表：角色/认领状态/联系方式确认状态；
- 联系方式编辑：本人可“保存并确认”，管理员/群主可“预填联系方式”（与 `GroupContactForm` 一致）；
- 待认领名单：添加/转正/删除；邀请创建/撤销（微信扩展，保留）；
- 权限角色调整、转让群主、删除成员，与 Web 权限一致。

### 4.7 导出（新增）

- 入口：群主/管理员（工作台“导出”）；
- 选项：导出内容（排班/统计）、时间范围（月/年）、岗位、成员（可选）；
- 流程：`POST /exports` 创建任务 → 轮询 `GET /exports/:id` → 完成后 `wx.downloadFile`（带 Bearer）→ 保存到本地/系统分享/用 `wx.openDocument` 打开 CSV；
- 审计与文件名规则沿用 Web `export-logic`。

### 4.8 平台运维控制台（新增 UI + 既有 API）

Web 目前只有 API 无界面，小程序补齐界面（这是新增 UI，不是移植缺失）：

- 任务运行列表：`GET /platform/jobs`；
- 备份列表：`GET /platform/backups`（当前内核只有列表接口，无下载接口，小程序先提供“查看列表”；如需下载备份，需新增后端接口，另行确认）；
- 平台用户状态：`PUT /platform/users/:userId/status`（停用/启用）；
- 节假日导入：`POST /holidays/import-preview` → `POST /holidays/import` → `GET /holidays/versions` → `POST /holidays/versions/:id/confirm` → `GET /holidays/coverage`；
- 权限：服务端 `PLATFORM_ADMIN_UIDS`（cloudbaseUid 白名单）不变；
- **最小后端扩展**：新增只读 `GET /platform/me` → `{ isPlatformAdmin: boolean }`，供小程序决定是否显示入口（不改权限判定，仅暴露查询）。

### 4.9 我的

- 真实姓名（微信注册时填写）、我的联系方式编辑确认；
- 退出登录（清会话回登录页）；
- 注销账号：`POST /users/me/deregister`（与 Web 能力一致，确认弹窗）；
- 平台管理员额外显示“平台运维”入口。

## 5. Web 修复/优化同步机制（防漏）

### 5.1 已由内核自动继承（无需移植）

Web 调试轮次中属于后端/契约/领域包的部分，小程序天然获得：

- 统一工作流冲突检查（换班/加扣班/请假）、失效工作流自愈与单调序列（轮次 55）；
- 请假重排策略、加扣班/换班预览与下一状态；
- 统计口径、节假日导入与确认、排班补录事件；
- Fastify 415 映射、日志脱敏、错误码契约、幂等并发；
- 微信登录/邀请/访客 key/订阅投递（任务 1–6 已实现）。

### 5.2 需要前端行为等价移植

| 来源 | 行为 | 小程序落点 |
| --- | --- | --- |
| 轮次 45 | 手动排班绘制模式、模板应用、紧凑排班配置（无轮值） | 手动排班页、排班配置页 |
| 轮次 45 | 模板应用起始日期 = 已排班之后首个未排日期 | 模板应用逻辑 |
| 轮次 48–54 | 换班/加扣班选项格式、冲突提示不被清空、具体请假冲突原因、岗位删除双重提示 | 请假/换班/加扣班表单与提示 |
| 轮次 58–61 | 开放当日、周末红/今天黄、六/日列名红色、补录配色 | 日历与补录网格 |
| fix-progress 各轮 | 读模型 zod 校验、错误文案模板、冲突处理 | 小程序 API 客户端错误映射与页面提示 |
| 现有 Web 单测 | `manual-schedule-logic.spec`、`statistics-logic.spec`、`calendar-views.spec`、`workflow-logic.spec` 等 | 移植为小程序 `utils/*.spec.ts` 等价测试 |

### 5.3 移植清单机制

- 新增 `docs/miniprogram-web-port-checklist.md`：一行为一个“Web 功能/修复 → 小程序实现 → 验证方式”，作为评审与验收的核对单；
- 每个模块完成时在清单打勾；未打勾不得宣称“已移植”。

## 6. 交互重设计范围

允许：

- 手动排班/补录：点选格子绘制（代替 hover + 点击）、长按清除、左右滑动切月；
- 日历：滑动切换月份、下拉刷新；
- 动画：页面转场、加载骨架、确认弹层过渡；
- 布局：卡片化、底部标签、半屏弹层，保持 375×667 无横向滚动。

不允许：

- 改变接口参数、校验规则、错误码/文案口径、权限矩阵；
- 跳过 Web 已有的确认步骤（覆盖已发布排班、工作流撤销、已过日期、冲突/空缺确认）；
- 恢复已废弃的轮值/自动生成入口。

## 7. 验证与验收

1. 每批：`pnpm miniprogram:typecheck`、`pnpm miniprogram:lint`、`pnpm verify`；涉及 contracts/api 时先构建并跑隔离 MySQL 集成测试；
2. 移植的工具逻辑：`utils/*.spec.ts` 与 Web 对应 spec 断言一致；
3. 模拟器逐页截图冒烟（`miniprogram-smoke.mjs` 扩展覆盖全部页面）；
4. 关键流程人工走查：创建群组 → 添加成员 → 邀请加入 → 班种/岗位配置 → 手动排班绘制 → 草稿发布 → 补录 → 统计 → 导出 → 平台运维；
5. 验收标准：除微信专属能力与移动端交互外，功能面与 Web 完全一致；未打勾的清单项不得宣称完成。

## 8. 分批实施概览（详细计划另行编写）

- 批次 A：信息架构重排（工作台 Hub、我的、导航角色过滤）、删除轮值/自动生成、排班配置重写、日历节假日标签；
- 批次 B：手动排班重写（绘制/模板/草稿批次/发布记录/冲突确认）；
- 批次 C：排班补录、统计补齐、成员联系方式、导出；
- 批次 D：平台运维控制台（含 `GET /platform/me` 最小后端扩展）、节假日导入；
- 批次 E：移植清单全量走查、模拟器冒烟、文档与验收。

## 9. 风险与待确认

- `PLATFORM_ADMIN_UIDS`：需要在服务器配置你的微信账号 cloudbaseUid（`wx_` 开头），小程序才能显示平台运维入口；
- `wx.downloadFile` 合法域名：导出下载与 request 域名一样需在小程序后台配置（`https://hosp.schedule.eylinhome.top`），备案前真机调试依赖“打开调试”绕过；
- 旧设计文档与本设计冲突时，以本文档为准；旧实施计划任务 13 内容作废，后续计划重写。
