# 小程序安全测试工具设计规格

- 日期：2026-08-31
- 批准依据：用户确认按推荐方案实施，并追加 release、脱敏、只读、有界内存和小米 14 验收约束
- 权威范围：`docs/audit/AUDIT_MASTER_PLAN.md` 第 7～8 节

## 目标和范围

在“更多 → 测试工具”提供面向非技术用户的安全诊断页。页面位于非首屏
`subpackages/diagnostics` 分包，保留旧手势探针并从“交互检查”进入。不得修改 API、数据库、权限、
认证、业务请求语义、`setData` 行为或无关业务页面，不增加依赖，不上传体验版。

## 环境和安全边界

- `develop`、`trial` 显示入口并允许访问；`release` 不显示入口。
- 测试工具页和旧手势探针直接访问时再次检查环境；`release` 在读取设备、网络、存储或初始化手势状态前返回工作台。
- App 仅在 `develop/trial` 创建有界内存仓库；`release` 不创建仓库，也不增加网络、错误、内存或生命周期监听。
- 复用既有统一请求函数与遥测调用点，只追加异常吞掉的同步摘要记录；不 monkey patch，不改变重试、Header、
  body、Promise、异常、receiver、调用次数或业务时序。
- 请求上限 20、错误 10、性能 12；不持久化、不上传，退出进程即消失。

## 脱敏模型

请求仅保留方法、允许列表中的固定路径段、`:value` 占位、开始时间、耗时、HTTP 状态、结果、重试和
近邻重复标记。查询串、主机、动态路径值、Header、请求体和响应体不进入仓库。

错误只保留固定页面、固定错误码和现有 SHA-256 堆栈指纹。报告不包含 token、Cookie、Authorization、
openid、手机号、姓名、群组成员、业务正文、存储键名/值、原始堆栈或可反推出身份的数据。构建描述若
不满足安全 ASCII 白名单则整体替换为 `redacted-build-description`。

## 页面结构

视觉方向为“设备体检单”：顶部蓝色构建校准条持续回答环境、版本和安全状态；卡片按版本、设备、显示
检查、关键场景、性能、网络、错误、存储和报告顺序排列。每项都写明是否正常、可能影响和截图位置。
320px 单列且无横向溢出；技术值允许换行。旧手势探针保持独立路由，测试工具场景卡提供入口。

## 验收

- 环境矩阵覆盖 develop/trial/release、入口、直接路径和 release 零诊断仓库。
- 定向测试覆盖内存上限、路径脱敏、报告结构、敏感词禁入和旧探针保护。
- 运行 Mini build/typecheck/test/source/verify/package/determinism/CI dry-run 与任务 lint/format。
- Storybook 390/320/大字号只作辅助黄金；原生视觉、交互、Console 和真机性能必须由匹配 SHA 的
  小米 14 体验版人工复核。
