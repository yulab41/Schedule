# Feedback23 导出布局、访客周视图与成员绑定二维码设计

## 目标与范围

本批次包含三个边界清晰的改动：修复导出页自绘选择器越过表单内边距；让匿名访客日历复用成员日历的展示核心；为群主、群管理员和平台管理员提供指定账号的一次性微信绑定二维码。访客电话和事件权限同时开放，但完整手机号仍必须通过成员对当前群组的有效同意门槛。

不修改成员日历；复用既有公共月历组件、`WorkbenchViewModel`、折叠 helper 和成员日历样式。访客仅补齐缺失的模板绑定和周高状态。不改变密码登录，不允许二维码绕过账号冲突检查，不在二维码参数中放姓名、工号、群组码或其他个人资料，不提交审核或正式发布。

## 已确认原因

导出页直接把 `ui-selector` 放在卡片 flex 容器下，没有像手动排班页一样使用带左右内边距的字段容器；共享选择器自身的 `width: 100%` 因此贴到卡片边界。修复应限定在导出页包装层，不修改共享组件。

访客与成员使用同一个 `WorkbenchViewModel`，其中已经同时提供 `duties` 和 `shiftGroups`。成员模板在 `e94a54ca` 后改为循环 `shiftGroups` 并使用 `shiftGroup.tint`；访客模板仍循环旧 `duties`，所以缺少浅色背景。这是同版本模板同步遗漏，不是两个日历版本或组件缺失。

## 方案比较与选择

### 导出选择器

1. 修改共享 `ui-selector` 宽度：会影响手动排班和其他页面，风险不必要。
2. 在导出页增加字段包装层：与现有表单模式一致，影响最小。采用此方案。
3. 用负宽度或 `calc()` 修补：依赖宿主渲染细节，不采用。

### 日历展示复用

1. 继续复制成员模板到访客页：短期局部，但会长期保留重复 WXML/WXSS、包体和漂移风险，不采用。
2. 新抽取完整共享展示组件：会重写已验收成员模板，并增加组件属性传输和事件转发；实时追随未来更新已不再是验收目标，因此收益不足以抵消成员回归和首屏开销，不采用。
3. 让访客直接进入成员页面并在前端隐藏敏感内容：权限边界脆弱，且会耦合成员导航和登录态，不采用。
4. 保持成员页面不变，访客复用已经存在的公共月历、ViewModel、折叠 helper 和成员WXSS，只补访客缺失的结构绑定：复用程度与运行风险平衡最好。采用此方案。

### 绑定二维码

1. 复用现有 `wechat_admin_binding_tickets`、微信身份事务锁、预览/确认和审计，只扩展授权主体、账号资料与小程序码生成：安全边界成熟。采用此方案。
2. 新建独立二维码令牌表和绑定流程：重复安全逻辑，增加竞态和迁移成本，不采用。
3. 生成包含账号密码或可重复链接的普通二维码：泄露风险高，不采用。

## 导出布局设计

两个 `ui-selector` 分别放入导出页本地 `.selector-field` 容器。容器沿用其他字段的 12px 左右内边距和 `min-width: 0`；选择器保持 100% 宽度。多选逻辑、弹层方向、共享组件和其他页面不变。320px 与 390px 均要求选择器边框完全落在表单卡片内，左右间距与“文件类型”字段一致。

## 共享日历展示及访客权限设计

访客继续消费既有 `WorkbenchViewModel`，月历继续使用公共 `calendar-month`，页面样式继续直接导入成员日历WXSS。访客周单元格改用模型已有的 `shiftGroups/tint`；详情卡片接入公共班种/电话折叠 helper、工作状态和成员同口径周高缓存。成员页面、路由、数据读取和事件处理不变。

访客页不得通过CSS隐藏代替服务端授权。API仍在响应层裁剪不应暴露的数据；电话和事件仅绑定访客已有的安全动作。这个方案保留少量页面WXML结构，但避免新增组件属性传输、重复样式和成员页重构，符合本轮“匹配当前成员页面、包体和加载优先，未来自动同步非目标”的最终选择。

匿名访客可在当天详情中查看电话入口和事件记录。电话数据在 API 侧只返回满足当前群组有效手机号同意的成员号码；撤回同意、手机号变化导致同意失效或群组不匹配时立即不返回。短号与完整手机号沿用现有联系人展示语义。事件仅返回访客允许的排班业务事件，排除内部审计、请求标识、操作者内部身份及管理操作元数据。所有访客读取继续受访客凭证、群组、排班发布状态、限流和失效控制约束。

## 指定成员绑定二维码设计

### 生成权限与前置检查

- 群主和群管理员只能为本群有效、待绑定的成员账号生成。
- 平台管理员可为任意符合条件的有效账号生成。
- 生成前在事务内检查目标账号仍有效、目标成员仍属于指定群组、账号没有有效微信 Mini 身份、账号版本未变化。已经绑定时返回明确的“已绑定，无需生成”，不创建票据、不生成二维码。
- 同一目标的新二维码创建成功后撤销其其他 pending 票据，避免多张有效码并存。

### 二维码身份与图片

二维码内部只携带不可猜测的一次性 ticket/scene；服务端只持久化 ticket 哈希。票据默认有效10分钟，使用一次即变为 consumed，管理员可以提前撤销。二维码打开现有或扩展后的绑定确认页，不自动绑定。

保存图片由小程序码和可读信息卡组成，明确显示：群组名称、群组码、用户姓名、工号、有效截止时间，并标注“一次性微信绑定码，请勿公开”。这些文字用于人工区分，不进入 scene，也不作为服务端授权依据。图片只在当前页面生成和展示，不写入业务缓存；长按保存沿用已有二维码能力。

### 扫码确认与冲突

扫码进入后，先预览群组名称、掩码姓名、掩码工号和到期时间；用户主动点击“确认绑定”后调用 `wx.login`。服务端再次锁定 ticket、目标账号和微信身份范围，复核权限产生时的账号版本、成员关系、未绑定状态及票据状态，然后绑定并消费票据、写审计、签发登录会话。

如果扫码微信已经绑定其他有效账号、目标账号已被别人绑定、成员已离群、票据过期/撤销/使用或账号版本变化，拒绝绑定且不迁移任何身份。后台管理员仍使用同一事务和冲突规则，不能强制覆盖。

## API、数据与审计

优先扩展现有绑定票据而不是新增平行模型。票据需记录可验证的发起角色、可选群组/成员上下文和目标账号版本；原始 ticket、二维码图片与可读个人资料不进入审计日志。创建响应返回二维码图片及展示所需的已授权字段，预览响应只返回掩码字段。

审计至少区分：群组管理员/平台管理员创建、撤销、扫码确认成功及冲突失败；记录目标用户ID、群组ID、到期时间和结果，不记录原始 ticket、openid、UnionID、手机号或二维码图片。

## 错误处理

- 已绑定：阻止生成并显示当前绑定状态。
- 生成微信小程序码失败：票据不得对用户宣称可用；允许对同一幂等操作安全重试。
- 过期、撤销、已使用：扫码页显示对应状态并提供返回登录，不重复调用 `wx.login`。
- 身份冲突：不自动解绑或覆盖，提示联系群主或平台管理员。
- 电话未同意：访客详情不显示号码，不以错误占位泄露成员是否留有号码。

## 测试与验收

- 先建立旧代码失败的布局回归：320/390 宽度下选择器左右边界与文件类型字段一致。
- 冻结成员月/周/列表、详情排序、折叠、状态和周高行为基线；成员页面文件不修改。
- 访客与成员在相同公开数据和 capability 下验证视觉结构、交互事件、浅色分组、多人同班种、状态、变更标记、空日和自适应高度等价。
- 比较抽取前后 Mini 主包/总包体和页面构建耗时；只报告实测结果，不预设一定改善。
- API 集成覆盖群主、群管理员、普通成员、跨群、平台管理员、已绑定、离群、过期、撤销、并发消费和微信身份冲突。
- 访客电话覆盖同意、撤回、手机号变化失效和跨群隔离；事件覆盖公开字段白名单和内部字段拒绝。
- Mini 覆盖二维码信息卡、长按、预览、确认、失败状态及不把 ticket/个人资料写入持久缓存。
- 运行受影响定向测试、Mini typecheck/lint/build、图标 parity、Worklet、包体和确定性。自动化不代替小米14验收。
