# 小程序“我的”页 Web 对等与微信头像设计

- 日期：2026-08-27
- 状态：用户已完成页面、数据、安全与验收设计确认
- 范围：小程序个人中心、个人值班概览、微信小程序身份状态、账号头像、密码与退出交互
- 不包含：工作台顶部头像替换、通讯录/群组成员头像、真实微信号展示、审核或正式发布

## 1. 目标与验收

以生产 Web `MyProfileView` 及其 Production Story 为唯一黄金源。小程序内容顺序固定为：

1. 页面标题；
2. 身份卡；
3. 值班概览；
4. 近四月值班节奏；
5. 下一班；
6. 账户设置；
7. 退出登录。

功能、状态、权限和交互语义必须 100% 对等；390×844 稳定截图区域目标相似度不低于 98%，
显著差异像素不高于 2%，关键几何偏差不高于 2px。另验证 320×844、系统大字号、减少动态、
访客、无头像、绑定/未绑定、加载/错误与下一班有/无。系统状态栏、胶囊和字体栅格只使用
版本化固定遮罩。

设计不另造“小程序风格”。现有浅灰背景、白色卡片、Web 同源蓝色、圆角与阴影保持安静，
深蓝“下一班”卡是页面唯一视觉签名。微信专属能力只作为账户明细行，不增加第二个视觉焦点。

## 2. 页面信息与交互

身份卡显示账号头像或姓名首字、真实姓名、已验证、当前群组身份、群组名称和正常状态。非访客
显示值班概览、趋势与下一班；访客与 Web 一样隐藏三块个人值班数据。没有当前群组时仍显示账号
身份，群组字段为未加入状态，不读取或猜测业务资料。

账户设置保留 Web 的姓名、当前群组、群组身份、手机号、短号、登录状态和修改密码，并在登录
状态之后增加：

- `微信小程序身份`：只显示已绑定/未绑定和合规解绑操作；
- `微信头像`：显示已同步/未设置，并在有头像时提供“恢复姓名首字”。

真实微信号、OpenID 和 UnionID 永不返回或展示。旧版“切换登录方式”卡、资料版本和旧隐私尾注
不再显示。工作台顶部个人入口保持现有图标；同步头像只用于页面标题和身份卡。

“查看完整统计”进入现有统计分包；“打开排班日历”在嵌入工作台时切回日历，独立 Profile Page
则回到工作台日历。修改密码使用原生安全表单：密码登录以当前密码证明，微信登录以新
`wx.login` code 证明。成功后既有 `authVersion` 语义使旧会话失效，并要求重新登录。退出登录不
删除业务资料、服务端头像或微信绑定。

## 3. 共享数据与降级

Web 当前 `MyProfileOverview` 构建逻辑迁入 `@schedule/presentation-core`，Web 只更换导入。Mini 用
现有成员、联系方式、月统计、年统计、当月日历与下月日历接口调用同一纯函数，保持当前成员
识别、特殊日期、四月趋势和下一班选择完全一致。

成员列表是主请求；失败时整块显示错误与重试。其余五个请求使用 Web 已有的
`Promise.allSettled` 语义：联系方式或日历失败时保留可用内容；月/年统计同时失败时显示个人统计
错误；陈旧群组请求不得覆盖新群组。嵌入组件常驻时保留已加载状态，仅在群组变化或用户重试时
重新请求。

## 4. 头像数据与接口

账号头像存入 MySQL 独立 `user_profile_avatars` 表，不写入 `user_profiles` 大字段，也不增加 OSS。
每个用户至多一行，保存内容、MIME、字节数、SHA-256 和独立递增版本；随现有生产数据库备份
恢复。只接受经魔数复核的 JPEG、PNG、WebP，最大 1 MiB；SVG、GIF、空文件、伪造 MIME 和超限
请求均拒绝。

公共契约增加可选 `UserProfile.avatarVersion`。图片本身不进入 JSON。受保护接口为：

- `PUT /users/me/avatar`：原始图片 body，成功返回新 `avatarVersion`；
- `GET /users/me/avatar`：返回认证图片、ETag、私有缓存和 `nosniff`；
- `DELETE /users/me/avatar`：幂等删除并返回 `removed`；
- `GET /me/wechat/miniprogram/binding`：只返回 `bound` 与 `canUnbind`。

头像版本与姓名资料版本独立；并发上传最后一次成功事务生效。删除头像后跨设备均回退到姓名首字。
解绑只解除当前正式 AppID 的身份，不删除头像。

## 5. 微信登录刷新与本地缓存

微信快捷登录使用官方 `chooseAvatar`，普通 tap 立即继续现有登录，取消选择不会阻断登录。选择
成功只暂存临时路径；已绑定登录、密码绑定或首次建档最终成功并建立 Bearer 会话后才上传。密码
登录先清除未完成的待上传头像，永不刷新头像。上传失败只显示一次“本次头像未更新”，保留旧
头像且不自动重试。

Mini 按 userId/avatarVersion 在 `wx.env.USER_DATA_PATH` 保存私有副本。页面只在本地版本缺失或不
匹配时认证下载；退出清除本地副本，服务端头像保留。恢复姓名首字前必须确认，成功后同时清除
服务端行、本地文件和缓存元数据。

## 6. 安全、可访问性与失败处理

- 所有头像与绑定接口要求 Bearer；用户只能读写自身数据。
- 图片响应不得公开 URL、URL token 或跨用户缓存；日志、遥测和错误不记录图片、标识符或正文。
- 写操作 loading 时禁用重复提交；解绑继续使用幂等键与新微信 code。
- 图标使用现有同源 SVG；结构图标不使用 emoji。触控区至少 44px，相邻操作至少 8px。
- 输入有可见标签，错误说明原因和恢复动作；颜色不作为唯一状态，读屏顺序与视觉顺序一致。
- 头像、统计或日历失败都不得清除有效会话或阻断其余个人资料。

## 7. 验证与发布边界

测试先行覆盖共享聚合等价、请求降级、头像类型/大小/隔离/版本、绑定资格、登录头像竞态、缓存、
删除、密码/解绑、导航和会话清理。触及 `packages/contracts/src` 必须运行浏览器 smoke 与 core smoke；
Mini 另运行全量、typecheck、production verify、确定性、包边界和体验上传门禁。

自动验证完成后状态为“已完成（含运行验证）→ 待用户复核”。从精确干净 checkpoint 上传下一
单调 production-profile 体验版并追加正式 allowlist；不提交审核、不正式发布。实体 Android 的
明确反馈才是原生视觉与交互验收结论。
