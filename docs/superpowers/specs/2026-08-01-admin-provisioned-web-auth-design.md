# 管理员创建账号与 Web 登录修订设计

- 日期：2026-08-01
- 状态：用户已确认，已实施
- 影响：替代主设计第 4.1 节中 Web 自注册的要求，并要求后续修订实施计划的任务 6 和任务 7

## 1. 目标与范围

Web 应用只向已存在的账号提供登录，不提供注册、邮箱、短信或验证码页面。CloudBase 账号由授权管理员在 CloudBase 控制台或未来的可信管理端创建；Web 和公开 API 都不拥有创建 CloudBase 账号的管理凭据。

本修订保留 CloudBase 作为密码、令牌和稳定 UID 的唯一所有者。业务数据库仍只保存 UID 和业务资料，绝不保存明文密码。后续微信登录必须绑定到既有 CloudBase UID，继续使用同一业务资料和排班数据；本修订不实现小程序页面或绑定界面。

本修订不包含账号管理 UI、公开注册端点、账号别名表或管理员创建账号的服务端 API。

## 2. 登录账号与密码规则

管理员创建登录账号时必须采用小写规范形式。Web 登录提交前对登录账号执行去除首尾空白和 ASCII 小写化，因此 `LINENYU`、`Linenyu` 与 `linenyu` 使用相同的 CloudBase 账号。CloudBase 原生用户名大小写敏感，规范化创建和规范化登录共同保证本产品的大小写无关行为。

密码在 Web 登录表单中仅要求非空，不设置长度、字符类型或复杂度规则；其值原样发送给 CloudBase，之后立即从组件状态清除。若 CloudBase 对管理员创建的账号密码施加平台规则，由可信创建端显示安全的错误信息。密码不得写入业务数据库、Pinia 状态、日志、错误消息或测试快照。

## 3. Web 交互与会话

1. 登录页字段使用“登录账号”和“密码”标签；不显示注册链接、邮箱字段或验证码输入。
2. `/register` 保留为兼容地址并重定向到 `/login`，不会显示或触发注册流程。
3. 登录成功后，现有会话恢复、当前资料读取、资料补全、受保护路由和退出登录行为保持不变。
4. 登录失败继续使用现有安全错误提示，且不得区分账号是否存在；401、403、409 和网络故障仍按统一错误协议处理。

## 4. 安全与运维边界

- CloudBase 必须启用用户名密码登录方式。
- 账号创建只由项目管理员执行，并记录在 CloudBase 的受控管理面；浏览器不获得 CloudBase 管理密钥，也不调用管理 API。
- 登录尝试继续依赖 CloudBase 的安全能力和服务端限频策略；不因移除邮箱验证码而新增匿名身份或绕过受保护路由。
- 管理员创建账号时采用小写规范账号。账号创建或微信身份绑定的完整运维流程随 CloudBase 部署和管理能力在后续任务中验证。

## 5. 验收与测试

- 路由中不再提供 Web 注册页面，访问旧 `/register` 自动回到登录页。
- 登录请求在调用 CloudBase 前规范化登录账号；不同大小写输入产生相同的 SDK 请求。
- 密码输入不设置最小长度、最大长度或字符模式，且不会被应用状态保留。
- 既有会话恢复、资料补全、退出登录、401 清理和受保护路由测试继续通过。
- 文档和状态交接明确：账号必须由管理员创建，未来微信身份绑定到同一 UID。
