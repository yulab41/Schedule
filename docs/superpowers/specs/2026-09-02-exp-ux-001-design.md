# EXP-UX-001 体验版真机反馈修复设计

## 目标与范围

本批次处理小米 14 体验版反馈中的四类可见交互问题：

1. 工作台内嵌换班表单的底部 sheet 被首页固定导航遮挡，正文不能独立滚动，底部操作不稳定。
2. 工作流共用选择器再次点击同一触发器时不能关闭。
3. 请假、加扣班直达页以及同根因的换班直达页错误挂载旧工作流底部导航。
4. 所有页面右上角静态 `P5`、`P7`、`P8`、`P9` 阶段标签仍对用户可见。

本批次不处理日期选择器业务、事件记录、全局图标重构、`MINI-G1-004`、体验版上传、production 部署或微信开发者工具操作。现有 `buildLabel`、SHA/版本编译变量、测试工具内部诊断 metadata 和 P1 页面左侧诊断说明继续保留。

基线为 fetch 后的 `origin/main@07decdbbf8bd4eaf7c34077392aea3b1fbc4eac2`，修复在独立分支/worktree `codex/fix-exp-ux-001` / `runtime/external-project-worktrees/exp-ux-001` 完成。

## 根因证据

### 换班 sheet

工作台的 `bottom-nav` 是页面级 `position: fixed`，使用导航层级 token；内嵌换班 panel 的旧 `sheet-layer` 却是组件局部 `position: absolute; z-index: 40`，表单 sheet 依赖 panel 的局部高度和 `overflow`。因此 sheet 与页面导航存在兄弟层级竞争，sheet 的底部也不是稳定的窗口底部。旧表单把生成预览/提交按钮放在正文 `scroll-view` 内，且没有共享 `ui-sheet` 的顶部 drag zone、阈值回弹和安全区外壳。

通讯录筛选 sheet 已采用 fixed layer、独立 `scroll-view` 和独立顶部 drag region；仓库既有 `ui-sheet` 已提供 fixed layer、统一对话层级、标题/完成按钮、底部安全区和只从顶部 drag region 触发的 WXS 手势。它是本批换班 sheet 的共享外壳来源。

### workflow-picker

`subpackages/workflows/components/workflow-picker/index.ts` 的 `handleOpen` 当前先关闭其他实例并发出 `pickerrequestopen`，但没有先判断 `this.data.open`。所以同一实例再次点击仍进入打开路径。`pickerInstances`、workflow host 的 `closeFromParent` 和 selector/date/month 三类浮层已有基础互斥与清理能力，本批只补自身 toggle 和 host dispose 清理边界。

### 旧工作流底部导航

`bc32a4f1` 在 leave、swap、duty 三个共享 panel 模板中同时引入了 `bottom-nav` 节点、导航 handler、导航样式和 `64px + safe-area` 内容预留。工作台已经拥有真正的五项 Tab 导航，三个直达 Page 是非 Tab 路由，因此该节点是同一根因的遗留副作用。删除三份节点及专用代码不会改变 `wx.navigateTo`/`wx.redirectTo` 直达路由、左上角返回或系统侧滑返回。

### 右上角阶段标签

源码追踪到 13 个静态 header `phase-chip` 节点：P5 两个、P7 三个、P8 四个、P9 四个。它们不是 build 变量、debug 状态或测试工具 metadata，而是模板中的可见节点；对应 CSS 在多个 panel/page 中单独或与其他 badge 合并。导出页的 `CSV` 复用了 `phase-chip` 样式，改用独立 `format-chip` 后才能删除 phase 样式链路并准确测量包体。

## 方案与决策

采用“复用共享 sheet + 共享 picker 修复 + 同根因源码清理”的最小方案：

- 换班 request、管理员直换、撤销三个 modal 均改用既有 `ui-sheet`。request/admin 的正文使用独立滚动区，preview/submit 操作移到滚动区外的固定 footer；撤销保持现有业务关闭/确认语义。下滑关闭只在非忙碌状态允许，避免关闭被业务拒绝后 sheet 已经被视觉移出。
- 不复制新的近似 bottom-sheet，不迁移通讯录专用筛选 sheet，也不改 leave/duty 直达页既有业务 modal；本批换班故障路径统一进入既有共享外壳。
- `workflow-picker.handleOpen` 的已开分支只执行一次 `closePicker` 并立即返回；未开分支继续关闭同作用域其他实例、发出一次打开请求、保留上/下展开计算和选择后关闭。workflow controller dispose/unload 主动调用 `closeFromParent`，防止旧浮层残留。
- 从 leave、swap、duty 三个 workflow panel 源码删除旧 bottom-nav 节点和只服务它们的 handler/style；普通直达页正文仅保留必要底部安全区 padding，embedded swap 继续由工作台页面级导航承载。
- 删除所有 header `phase-chip` P 节点及仅服务它们的样式；CSV 使用 `format-chip`。保留 build identity、P1 左侧说明和业务状态 badge。

只改固定层级会比复用 `ui-sheet` 少改几行，但会保留重复外壳、正文按钮滚动和手势缺口；把所有工作流与通讯录 sheet 一起重写则扩大原生回归风险。因此不采用这两种方案。

## 行为合同

### Sheet

- layer fixed 且高于工作台页面级导航；panel 使用共享高度/安全区规则，顶部约位于可用窗口四分之一附近。
- 标题、把手、完成/关闭入口和 footer 始终可见；正文仅由独立滚动区滚动。
- drag 事件只绑定顶部 drag region；正文、picker 下拉层和 footer 的上下滑动不触发关闭。
- 未达到距离/速度阈值或 touch cancel 时回弹；达到阈值后只发出一次 swipe close。
- 完成、取消、遮罩和忙碌保护保持原有语义。

### Picker

- 关闭→点击打开；打开→再次点击同一触发器关闭。
- A 打开时点击 B：关闭 A、打开 B；选项选择后关闭。
- 外部点击、sheet 关闭、页面 unload/context dispose 后关闭并清理；同一作用域最多一个打开层。
- 空选项仍可通过同一触发器关闭；现有自动向上/向下展开不变；不产生二次 toggle、事件穿透或立即重开。

### Page shell 与标签

- leave/swap/duty 直达页不含旧 `bottom-nav`、导航 handler 或导航专用底部占位；路由、header back 和系统返回保留。
- 所有右上角 P 阶段 chip 从 WXML/样式源中删除；构建版本追踪仍通过内部 `buildLabel`/metadata 工作。
