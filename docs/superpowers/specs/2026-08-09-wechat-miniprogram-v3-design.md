- 状态：已获用户确认，等待用户审阅本文件后编写实施计划

## 1. 权威顺序与设计目标

V3 的行为基准按以下顺序解释：

1. Web 当前运行代码和用户确认后的 Web 视觉基线。
2. 本设计文档。
3. 用户审阅后的 V3 实施计划。
4. 调试日志和项目状态中的当前批次记录。

2026-08-08 的小程序设计、移植设计、实施计划和清单全部作废，不能作为 V3 的需求来源。Git 历史保留用于追溯，但工作树不得保留旧页面或旧计划来影响后续实现。

V3 的目标不是把桌面布局缩小，而是保持 Web 的业务语义和视觉细节，同时把输入方式改成适合手指的触控、滑动和底部面板交互。

## 3. 1:1 保留与移动端适配

### 3.1 必须 1:1

以下是跨平台业务和视觉契约，不能因移动屏幕变窄而省略：

- 日期、星期、今天、周末、过去日期、业务月份和排序。
- 每个日期的全部排班，不得只取第一条；显示成员全名、角色、班种全称/简称和时间。
- 班种字体、前景色、背景填充、边框、圆角、状态图标和排列顺序。
- 节假日名称、放假日/调休工作日状态，以及对应字体色、填充色和边框。
- 换班、请假替班、加班、扣班等标识的文字、颜色、填充、边框、位置和点击目标。
- 事件详情中的前后人员、班次、操作者、原因、审批状态、关联链和统计影响。
- 请假、换班、加扣班申请及审批的字段、预览、策略、确认、撤回、取消、权限和错误文案。
- 手动排班的人员行、日期列、班种选择、清空、撤销、草稿、发布、冲突和版本保护。

Web 中已知的节假日 class 绑定缺陷必须在 V3 日历实现前修正，并以修正后的 Web 截图和令牌作为黄金基线；V3 不复制一个已知的 Web 缺陷作为“1:1”。

### 3.2 允许适配

- 鼠标点击改为手指点击；hover 改为 pressed、selected 和 focus-visible 状态。
- 滚轮、月份按钮改为横向滑动和年月选择器。
- 桌面弹窗改为可下滑关闭的 Bottom Sheet。
- 桌面宽表格改为可横向滚动的网格，并用轴向锁定避免误触。
- 鼠标拖拽填班改为点击选中、底部班种面板、长按清除和显式行列操作。
- 桌面侧边栏改为原生 tabBar、页面内分组和抽屉，但角色过滤和入口权限不变。

## 4. 组件和插件决策

### 4.1 原生微信能力

- 月份切换使用三页 `<swiper>`，固定为上月、当前月、下月，开启 `circular` 和 `enhanced`。
- 只渲染当前月及前后各一个月；循环切页必须用触摸来源、目标月份和请求序号保护，不能因回调重复加载或跳回。
- 使用 `touchstart/touchmove/touchend` 实现水平滑动、方向锁定、长按和面板下滑关闭。
- 使用 `<scroll-view>` 管理页面纵向滚动和手动排班横向滚动。
- 使用原生 `<picker>`、`wx.showActionSheet`、拨号能力和分享能力处理平台级交互。
- 动画优先使用 CSS `transform/opacity/transition`；只有跨页面或复杂序列确有必要时使用 `wx.createAnimation`。

动画基线：月份切换 240ms、Bottom Sheet 280ms、按压和选择反馈 200ms，统一 `ease-out`；不在密集日历区域使用不可预测的弹簧位移。

### 4.2 TDesign 小程序

继续使用仓库已有的 `tdesign-miniprogram`，仅用于按钮、输入、单元格、开关、基础弹窗、提示和表单反馈等通用控件。所有组件按需引入，不能用全量注册掩盖包体积问题。

日历网格、排班单元格、标识徽章、节假日标签、事件时间线、Bottom Sheet 和手动排班面板均由 V3 组件自绘，以便控制 Web 所需的字体、填充、边框和事件区域。

### 4.3 暂不新增的库

- 不安装 WeUI、Vant Weapp 或 ColorUI。
- 不直接安装 `wx_calendar` 或其他通用日历组件。
- 若某个具体需求被证明无法通过原生能力和现有 TDesign 完成，必须先提交一次短期 spike，记录包体积增量、维护活跃度、主题覆盖能力、事件标记能力和 Web 对照截图；spike 未通过不得加入依赖。

这样可以避免两个基础组件库互相覆盖，也避免通用日历组件抹平本项目的排班和变动语义。

## 5. V3 客户端架构

表现层按以下边界重建：

- `app-shell`：启动、会话恢复、原生 tabBar、角色入口和全局错误反馈。
- `calendar-shell`：月份状态、三页 swiper、月/周/列表模式和刷新策略。
- `calendar-grid`：星期头、日期格、排班行、节假日标签、变动标识和日期点击。
- `assignment-row`：成员姓名、角色、班种、颜色令牌和电话入口。
- `marker-badge`：换、替、加、扣等类型化标识，独立于班种颜色。
- `holiday-tag`：放假日与调休工作日的独立视觉状态。
- `duty-detail-sheet`、`event-timeline-sheet`、`phone-sheet`、`confirm-sheet`：详情、事件、电话和确认流程。
- `manual-grid`、`shift-palette`、`manual-actions-sheet`：手动排班触控编辑。
- `request-form`、`preview-sheet`、`approval-sheet`：请假、换班、加扣班及审批流程。

页面只负责编排状态和导航；纯日期、筛选、排序和格式化逻辑必须有独立 TypeScript 模块和测试。业务状态仍由服务端 API 和共享契约决定。

## 6. 日历数据和视觉模型

V3 不允许 WXML 直接拼装服务端对象。日历接口数据先转换为完整的 `CalendarMonthViewModel`：

- 日期：业务日期、日号、星期、`isToday`、`isWeekend`、`isPast`。
- 节假日：名称、`isOffDay`、`isWorkday`、前景色、填充色和边框令牌。
- 排班数组：成员 ID、成员全名、角色、班种 ID、班种全称、简称、时间、班种前景色、背景色、边框和电话权限。
- 标识数组：标识类型、文案、关联事件 ID、字体色、填充色、边框、点击动作和权限。
- 页面状态：加载、局部加载、缓存、空日、错误、无权限和冲突刷新。

同一天多条排班必须保留顺序并分别渲染。排班姓名在首屏可见；次要时间和事件说明可在详情面板展开，但不能把姓名隐藏到点击之后。

### 6.1 标识语义

V3 以 Web 当前实际标识集合为准，明确区分：

- `swap`：换班，显示“换”。
- `leave`：请假造成的替班，显示“替”。
- `overtime`：加班，显示“加”。
- `deduction`：扣班，仅在相关成员个人事件或允许的上下文显示“扣”。

历史“调”标识是否显示由 Web 黄金基线决定；若 Web 当前已移除则小程序不重新添加。每个标识都必须是独立可点击区域，点击进入对应事件或详情，而不是拼接成普通文字。

### 6.2 触控规则

- 横向切月：横向位移达到屏幕宽度的 18% 或 48px（取较大值）才翻页；纵向位移超过横向位移时锁定为页面滚动。
- 日期点击：点击日期空白区域打开日期详情；点击排班行打开值班详情；点击标识打开事件详情。
- Bottom Sheet：内容滚动到顶部后，向下拖动 80px 或达到速度阈值才关闭，否则回弹。
- 长按：持续 500ms 且水平位移小于 12px 触发行/列操作，不与横向切月同时生效。
- 所有点击、长按和滑动区域保持稳定尺寸，不能因异步文案或徽章变化导致页面抖动。

## 7. 业务流程

所有流程使用“填写 → 服务端预览 → 影响确认 → 提交 → 状态刷新”的模型：

- 请假预览必须显示受影响班次、变更前后人员、顺延/原轮值策略、周末/节假日变化、连续值班、跨角色冲突和空缺。
- 换班预览必须显示双方两个班次的前后人员、资格、请假、时间冲突、自动接受和审批路径。
- 加扣班预览必须显示实际值班人员、成对加扣记录、原因、审批路径和净值变化；管理员直办也必须填写原因。
- 任意关键字段变化都清空旧预览并重新请求；提交前再次刷新并校验版本。
- 409 时展示服务端最新摘要和可执行的刷新/重新预览动作，不用旧预览强行提交。
- 申请中心、审批中心和事件中心必须按 Web 状态显示取消、接受、撤回、批准、驳回和归档动作，不能用一个通用确认框覆盖所有状态。

## 8. 手动排班交互

手动排班保留 Web 的人员行、日期列和班种选择语义，输入改为：

1. 选择岗位、成员、开始日期和周期天数。
2. 点击单元格进入 selected 状态。
3. 底部班种面板点击填入；再次点击当前班种可清空该格。
4. 长按单元格打开“清空此格/清空此行/清空此列”操作面板，行列清除必须二次确认。
5. 保存模板、应用模板和发布前显示冲突、请假、连续值班、节假日和统计影响。
6. 草稿、发布、撤回、重发和删除使用服务端版本保护；冲突时刷新而不是覆盖。

横向网格滚动和月份滑动分离处理：网格内先消费横向滚动，只有触摸起点在月份导航区域才触发月份切换。

## 9. 导航、权限和平台能力

默认使用原生 tabBar，入口为工作台、日历、通知、我的；角色过滤与 Web `workbenchNavItems` 保持一致。访客只能看到访客日历及允许的群组入口，普通成员不显示管理和事件管理入口，平台管理员入口由服务端 `GET /platform/me` 决定。

平台运维、群组管理、排班配置、补录、统计、导出、事件和通知均按 Web 的权限和状态实现，不因为移动端而静默隐藏必要的错误或审批影响。

## 10. 缓存、错误和安全

- `wx.setStorageSync` 只保存按用户、群组、业务月份和版本隔离的只读日历快照。
- 快照显示必须带时间戳和“可能不是最新数据”状态；服务端成功响应后覆盖缓存，变更成功后主动失效相关月份。
- 离线只允许查看已有快照，所有创建、审批、发布、撤回和清除操作必须阻断并解释原因。
- 401 清除会话并进入 V3 登录入口；权限错误不暴露其他群组数据；业务冲突显示后端原始原因和最新数据摘要。
- API、认证、契约和后端规则不在小程序复制；所有写操作依赖服务端事务、版本号和 operationId。

## 11. 性能与包体积

- 主包目标小于 2MB，按开发者工具实际编译产物测量，不按源代码体积估算。
- 页面和大型资源使用分包；第三方组件按需加载。
- 日历只保留当前月及前后月的视图模型，离开范围立即释放旧数据。
- 高频 scroll/touch 更新使用节流，禁止在每个触摸帧重新请求 API 或重建全页面数据。
- 验收记录首屏加载、切月、打开详情和打开 Bottom Sheet 的实际耗时。

## 13. 分阶段实施和停止条件

1. 清理 V2、保留基础设施、提交本设计文档；停止条件是旧文档/旧表现层不再出现在工作树，状态文件与 Git 一致。
2. 建立 V3 manifest、app-shell、tokens、导航和认证入口；停止条件是空壳可启动、角色入口正确、API 认证没有 UI 硬编码耦合。
3. 完成日历黄金基线和月/周/列表触控；停止条件是日历标识矩阵和 Web 对照截图通过。
4. 完成详情、事件、电话、请假、换班、加扣班及审批；停止条件是每条流程都具备预览、确认、409 和状态刷新。
5. 完成手动排班、补录、统计、导出、群组和平台页面；停止条件是权限、版本和发布流程通过。
6. 完成性能、包体积、模拟器和真机验收；停止条件是主包小于 2MB、核心触控无阻塞且用户确认。

每轮只实施 1–3 个任务；复杂日历、并发和发布任务独立成轮。任何阶段都不得提前恢复旧 V2 页面或旧移植清单。

## 14. 明确拒绝的方案

- 在 V2 页面上继续补 CSS 或补字段。
- 通过通用日历组件替代包含自定义标识的日历网格。
- 同时引入 WeUI、Vant 和 TDesign。
- 用本地缓存作为排班写入源或离线提交队列。
- 用一套通用确认弹窗覆盖请假、换班、加扣班、审批和发布状态。
- 用宽范围 Git 回退丢失 API、认证、契约或后端历史。
