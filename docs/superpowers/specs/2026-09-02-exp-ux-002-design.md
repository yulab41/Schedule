# EXP-UX-002 请假与加扣班弹窗外壳修复设计

## 目标与范围

本批处理用户对上一体验版反馈的两个剩余工作流弹窗问题：

1. 请假弹窗没有采用换班的共享高度、安全区、独立滚动和顶部下滑关闭外壳。
2. 加扣班的发起、管理员直达和撤销弹窗仍使用旧的局部弹窗外壳，没有顶部拖动手势。

基线为 fetch 后的 `origin/main@359966f7240d2f557b24dd0c1ac61979d6bb829`，执行分支/worktree 为
`codex/fix-exp-ux-002` / `runtime/external-project-worktrees/exp-ux-002`。本批不处理日期选择器业务、事件记录、全局
图标、P 标签、生产部署、体验版上传或微信开发者工具操作；换班只作为已经完成的共享实现参考，不改其业务语义。

## 根因证据

### 请假弹窗

`workflow-leave-panel/index.wxml` 的新建请假和预览审批都使用本地 `sheet-layer`、`sheet-scrim` 和
`native-sheet`。`index.wxss` 将 layer 设为组件内 `position:absolute; z-index:40; inset:0`；新建表单是
`height:auto; max-height:78vh`，审批弹窗是 `height:88%`。新建表单还把提交按钮放在正文 `scroll-view` 的
`sheet-body` 末尾。该外壳不引用 `ui-sheet`，没有顶部 drag region/WXS，也没有与窗口脱离的固定层级。

### 加扣班弹窗

`workflow-duty-panel/index.wxml` 的发起、管理员直达和撤销弹窗复用了同一套本地 layer/native-sheet；它通过
`@import '../workflow-swap-panel/index.wxss'` 间接得到旧样式，但没有任何 `ui-sheet` 节点或拖动事件。发起和
管理员表单的操作区也在正文滚动内容中，撤销弹窗没有滚动与顶部手势区。

### 对照实现与页面注册

`workflow-swap-panel` 已经使用 `components/ui/ui-sheet`：共享 layer 是 fixed/z400，panel 是 `78vh/max-height:660px`，
content 为 flex 外壳并保留 `env(safe-area-inset-bottom)`；标题和把手在共享 drag region 内，WXS 以 96px 位移或
28px/0.65 快速下滑关闭，未达到阈值或 cancel 会回弹。调用方把正文滚动区和操作 footer 分开，因此可作为唯一
工作流弹窗外壳参考。

三个直达页的 WXML 都是 include 对应 panel 模板。请假、加扣班页面 JSON 当前只显式注册
`workflow-picker`，而迁移后的 include 内容还需要 `ui-sheet`；本批会把直达页的 `ui-sheet` 注册补齐，并保持
路由和 Page/controller 生命周期不变。换班直达页只做同一 manifest 注册审查/必要补齐，不改换班业务模板。

历史定位：`git log -S`/`git blame` 显示请假旧表单由 `9fae3869` 引入，换班/加扣班共用旧工作流表单路径由
`80ddadf0` 与 `bc32a4f1` 引入；上一批 `3b1cbd1b` 只把工作台内嵌换班三种弹层迁移到 `ui-sheet`，明确没有迁移
请假和加扣班直达页业务弹窗。

## 方案与决策

采用“复用既有 `ui-sheet`，只迁移业务 slot 布局”的最小方案：

- 请假新建、请假审批、加扣班发起、加扣班管理员直达和加扣班撤销共五个弹窗改为 `ui-sheet`。
- 保留当前 controller 的 data 字段、事件 handler、API 调用、忙碌保护、完成/关闭/遮罩语义；共享组件的
  `close` 事件继续交给现有 `handleClose*` 方法处理。
- 正文统一使用 `workflow-sheet-scroll`；预览、冲突和表单字段留在滚动区内。提交、审批和撤销按钮放入
  `workflow-sheet-footer`，使其脱离正文滚动并始终位于 safe-area 之上。
- 工作流共用布局样式沿用现有 `workflow-leave-panel/index.wxss` → swap → duty 的共享 import 链，补充一次
  `workflow-sheet-scroll/footer/short-content` 规则，不另建近似弹窗组件。
- `swipe-dismiss` 绑定为对应 busy 状态的反值：业务提交/审批/撤销期间不允许手势关闭；其他时间由共享 WXS
  处理顶部 drag region。正文、选择器列表、footer 不拥有关闭手势。
- `ui-sheet` 的 fixed/z400 和安全区规则高于页面容器及任何首页 Tab 导航；不提高首页导航层级，不用任意大
  `z-index` 掩盖局部布局问题。

不采用以下方案：

1. 只给旧 `native-sheet` 增加高度和 WXS：会继续维护与 `ui-sheet` 重复的层级、回弹和安全区逻辑。
2. 为请假/加扣班新建一个工作流专用 sheet 组件：会复制已有共享组件的外壳与手势实现，增加未来漂移面。

## 行为合同

### Sheet 外壳

- layer 使用共享 `ui-sheet` 的 fixed/z400；panel 使用 `height:78vh; max-height:660px`，顶部位于可用视口
  上方约四分之一附近，内容约占四分之三。
- `ui-sheet__handle`、标题、完成/关闭入口始终在 drag region/header 中可见；页面底部安全区由共享 content
  padding 处理，footer 与其按钮不落入安全区。
- 正文只有一个 `scroll-view` 负责上下滚动，并以 `min-height:0; flex:1` 适配内容过长；footer 为
  `flex:none`，不随正文滚动。
- 下滑关闭只从顶部 drag region 开始。共享阈值、纵横轴判定、短拖回弹、cancel 回弹和单次 close 行为保持
  原实现：96px 位移，或至少 28px 且速度达到 0.65；横向、向上、正文和 picker 滑动不关闭。
- 完成、取消/确认、遮罩点击和 busy 期间的既有语义保持不变；一次共享 swipe close 只能进入一次现有关闭
  handler，不产生立即重开或事件穿透。

### 五个调用者

- 请假新建：`formVisible` 控制可见性，正文滚动字段和受影响班次，提交按钮固定在 footer。
- 请假审批：`approvalVisible` 控制可见性，审批预览/冲突/策略滚动，驳回和批准按钮在预览可用后固定在
  footer；现有 `approvalBusy` 防止业务处理中关闭。
- 加扣班发起/管理员直达：分别保持现有 `requestFormVisible`/`adminFormVisible`、预览和提交 handler，正文
  滚动与两个操作按钮分离。
- 加扣班撤销：保持 `revokeVisible`、原因输入和确认 handler，短正文与确认 footer 分离；busy 时不允许关闭。
- 三个直达 Page 明确声明 `ui-sheet`；页面仍是非 Tab `navigateTo` 页面，左上角返回和系统侧滑返回不变。

## 永久回归合同

先在旧源码上运行新增合同并记录红灯，再修改业务源码。新增或扩展 Mini 脚本必须位于
`apps/miniprogram/scripts`，由 `pnpm miniprogram:test` 的 `--dir scripts` 自动发现。合同至少证明：

- 请假两个弹窗、加扣班三个弹窗都使用共享 `ui-sheet`、`visible`、`swipe-dismiss` 和 `bind:close`；旧
  `sheet-layer/native-sheet` 结构会失败。
- 共享层为 fixed/z400、78vh/max660，包含 safe-area；正文 scroll 与 footer 是独立 flex 区域，按钮不在
  正文 `scroll-view` 内。
- 共享 WXS 覆盖顶部 drag zone、正文不接管 drag、阈值关闭、短拖/取消回弹、快速 flick 和单次 close；这些
  测试不宣称已经完成实体设备手感验收。
- 请假/加扣班直达页 JSON 注册实际需要的 `ui-sheet`，include 路由仍为非 Tab Page；页面源码没有旧底栏或
  为底栏预留的占位。
- 现有 controller 的 busy close guard、preview/submit/revoke handler 与页面生命周期回归继续通过。

## 验证与交付边界

最终在同一最终 tip 上运行受影响 sheet、workflow、page/lifecycle 测试，Mini 全量、TypeScript、production
build、`miniprogram:verify`、Prettier、ESLint、`git diff --check`、状态策略和 `smoke:check-core`。不调用
微信开发者工具，不上传体验版，不部署 production。

包体以干净 production build 的实际输出比较；只有 manifest/package audit 给出真实前后差值时报告变化。
`ui-sheet` 是既有共享代码，移除旧模板可能降低源码/产物，也可能因组件注册与样式复制口径而无变化，不能预先
承诺减少量。

自动化、静态构建和 `miniprogram-ci`（本批不调用上传）只能证明结构与编译，不等价于 Xiaomi 14 原生体验。下一
版仍需用户在与最终 SHA 一致的体验版上验证 sheet 高度、safe-area、正文滚动、顶部下滑回弹、picker 内部滚动、
按钮点击和系统侧滑返回。
