# 小程序选择器统一与长列表末项安全区设计

## 背景与已验证事实

体验版 `.182` 已让换班、请假和值班工作流内的 selector 按实际滚动区边界选择向上或向下展开，
并动态限制最大高度。小米 14 后续截图证明另有一个独立问题：长列表无论向上还是向下展开，
滚动到底后最后一项都可能贴近或侵入圆角边框。

共享模板当前把以下职责放在同一个 `scroll-view`：

- 纵向滚动；
- `max-height`；
- `6px` 内边距；
- 背景、边框、圆角和阴影。

选项又是该 `scroll-view` 的直接子节点。微信 WebView 在滚动到底时没有稳定地把外层底部
padding 计入可滚动内容安全区，因此末项会进入边框区域。该结构由 `6d0575d0` 引入；`.182`
只增加动态最大高度，没有引入这个盒模型缺陷。

开发者工具 390×844、基础库 3.17.2 的运行证据与用户截图一致：手动排班和导出成员的长列表
均能打开，目标页面 Console 没有 error，Network 没有 fail/error。这是模板/CSS 布局问题，不是
运行时异常、接口失败或方向算法错误。

## 用户确认的目标

1. 修复所有自定义列表选择器的末项侵入边框问题，向上、向下均覆盖。
2. 所有列表型选择菜单统一使用最新共享 `ui-selector`。
3. 邀请与访客的三个原生列表、排班补录岗位、测试工具版本目标全部去除原生 `picker`。
4. 排班配置的四个原生时间选择器复用已验证的年月滚轮体系。
5. 完成后生产源码中的原生 `<picker>` 数量为零。
6. 不复制年月选择器、不新增另一套滚轮状态机，不改变业务写入语义。

## 范围

### 列表选择器

- 现有 22 个自定义 selector 调用点：
  - 换班、请假和值班工作流 12 个 selector 模式；
  - 手动排班、导出排班、群组设置 10 个直接 `ui-selector`。
- 从原生 `picker` 迁移的 5 个列表：
  - 邀请对象；
  - 加入角色；
  - 邀请排班岗位；
  - 排班补录岗位；
  - 测试工具打开目标（体验版/正式版）。
- 迁移后共 27 个列表型调用点使用同一共享模板和放置契约。

### 时间选择器

- 排班配置新增班种的开始、结束时间。
- 排班配置编辑既有班种的开始、结束时间。
- 时间值继续使用 `HH:mm`，小时范围 `00`–`23`，分钟范围 `00`–`59`。

### 不纳入

- 日期月历、月份滚轮现有视觉和业务语义重做。
- API、数据库、排班写入、跨午夜规则、班种保存载荷修改。
- Portal、全局浮层管理器或框架迁移。
- 借本轮处理无关的 workbench 启动警告。

## 方案

### 1. 分离滚动视口与滚动内容

保留 `scroll-view` 作为弹层外壳，继续负责绝对定位、动态 `max-height`、背景、边框、圆角、阴影
和内容裁切。在它内部增加唯一内容容器，由内容容器承担 `6px` padding，所有选项和空态都放入
该容器。

这样底部 padding 成为真实滚动内容的一部分；到达滚动末端时，最后一项之后仍有明确安全区，
不会落进边框。现有 28px 行高、2px 行距、选中背景、上下动画和 300px 上限保持不变。

弹层期望高度仍为：

```text
选项行 28n + 行距 2(n-1) + 上下内边距 12 + 上下边框 2 = 30n + 12
```

因此 `.182` 的 `optionCount * 30 + 12` 几何估算无需另建常量体系，只需用测试把模板结构和
估算契约绑定起来。

### 2. 所有页面级列表使用真实滚动边界

`.182` 已覆盖工作流 `.workflow-sheet-scroll`。本轮为其余页面拥有者测量并传递边界：

- 手动排班 `.manual-page-scroll`；
- 导出排班 `.exports-scroll`；
- 群组设置 `.group-settings-scroll`；
- 邀请与访客 `.invite-visitor-scroll`；
- 排班补录 `.backfill-scroll`。

测试工具使用窗口级滚动，没有局部裁剪容器，继续使用共享组件的窗口边界回退。边界测量复用
工作流现有 `{ top, bottom }` 契约；页面打开 selector 时刷新，页面隐藏或卸载时不保留过期坐标。

### 3. 原生列表迁移保持事件语义

五个原生列表转换为 `ui-selector` 所需的 `{ value, label }` 选项。共享组件仍发送
`{ index, option, value: String(index) }`，现有处理器继续以 index 查找业务对象：

- 邀请对象、加入角色和岗位只更新本地草稿；
- 补录岗位只有值真正变化时才重新读取月历上下文；
- 测试工具只切换后续要打开的版本目标。

选择一次只发一次 change；再次点击同一值、关闭、页面隐藏和禁用态不增加业务副作用。

### 4. 在现有时间/日期组件中增加 `time` 模式

不创建复制版时间选择器，也不重命名现有组件。给已经承载 `selector`、`month`、`date` 的
`ui-date-picker` 增加 `time` 模式，复用同一个：

- picker 实例互斥集合；
- 底部 Sheet、标题、摘要、关闭与完成按钮；
- `ui-wheel-column` 的滚动、吸附、代际保护和选中态；
- 取消零提交、完成一次提交、重开定位当前值的生命周期。

时间模式显示两列：小时列单位为“时”，分钟列单位为“分”。合法 `HH:mm` 在打开时映射到两列；
空值沿用原生时间 picker 的行为，在草稿中定位当前本地时间，但取消不写值，只有完成后才提交；
非法值安全回退到同一草稿默认值，不抛错。确认事件继续为 `{ value: 'HH:mm' }`，现有
`handleNewShiftInput` / `handleShiftInput` 无需改变业务分支。

跨午夜、全天班、统计开关和最终 API payload 均保持原语义。

## 视觉与交互约束

本轮不创造新视觉方向。医疗排班用户需要快速识别当前值并可靠完成选择，因此列表沿用当前白色圆角
浮层、蓝色选中态和紧凑 28px 行；时间沿用换班年月选择器的白色底部 Sheet、中央双轨、淡出遮罩和
确认区。唯一视觉修正是让列表首末内容都尊重 6px 安全区。

320px 和 390px 宽度均不得横向溢出；大字体模式继续使用现有页面规则；减少动态偏好继续关闭弹层
入场动画，不影响滚动选择。

## 回归测试

### 先红后绿

- 模板契约：旧模板因选项直接位于带 padding 的 `scroll-view` 中失败；新模板要求唯一内容容器
  承担 padding。
- 几何契约：1、2、10、20 项以及上下两种方向，最后一项之后始终保留底部安全区。
- 调用点契约：生产源码没有 `<picker>`；27 个列表调用点全部使用共享组件；局部滚动页面全部传递
  可视边界。
- 原生列表迁移：五个处理器的值、index、禁用态和副作用次数与旧行为等价。
- 时间模式：合法值、空值、非法值、小时/分钟预览与 settle、取消、确认、重开、组件互斥。
- 现有 selector/month/date/controller 测试保持通过，证明成熟年月和日期路径未退化。

### 构建与运行

- 目标 Vitest、Mini typecheck、格式、lint、production Mini verify 和包体检查。
- 开发者工具 390×844 / 基础库 3.17.2：
  - 手动排班值班人员，向上和向下长列表滚到底；
  - 导出成员长列表滚到底；
  - 邀请三列表、补录岗位、测试目标；
  - 新增和编辑班种的开始/结束时间；
  - Console error/warn 与 Network fail/error 检查。
- 模拟器证据不替代小米 14；最终体验版需绑定干净 SHA 后再由用户验收。

## 风险与回滚

- 最大风险是扩展 `ui-date-picker` 时误伤已成熟的年月/日期状态。用模式分支、既有测试全量复跑和
  “现有模式模板/行为不变”契约控制，不做组件改名或泛化重构。
- 列表迁移风险是 native picker 与共享 selector 的事件 detail 不同。适配保持在展示选项和既有
  index 处理边界，不改业务模型。
- 页面边界测量失败时回退窗口，不阻断打开、选择或关闭。
- 回滚可按三块独立撤销：内容安全区、原生列表迁移、time 模式接入；不需要数据库或 API 回滚。

## 完成标准

- 生产源码中 `<picker>` 为零。
- 27 个列表型菜单均使用共享最新版，长列表上下展开滚到底都保留安全区。
- 四个时间字段使用共享滚轮，输出与原生控件相同的 `HH:mm`。
- 日期、月份、业务写入与跨午夜语义无回归。
- 自动化与开发者工具门禁通过；小米 14 结论单独标记。
