# 小程序通讯录修复与性能优化设计

## 目标与范围

修复通讯录 facets 尚未就绪时可打开空筛选弹层的问题，使小程序通讯录主体、筛选弹层、搜索结果和交互与当前 Web Storybook 通讯录组件一致。保留小程序顶部身份栏、系统胶囊、底部导航和通讯录内部模式 swiper。

本轮不新增或修改 API、数据库、公共 contracts，不改变收藏、常用、拨号权限、搜索排序、筛选语义、30 条分页和服务端最终鉴权。

## 已确认根因

- `handleOpenFilters` 在 facets 未就绪时仍进入打开路径，WXML 只遍历空 `filterSections`，形成空白弹层。
- 主体导览依赖同一份 `filterSections`，facets 未完成时整个导览消失，和 Web 的加载/错误状态不同。
- `syncFilterSections` 在双模式 facets 完成后立即构建两套完整选项树并放进页面 data；关闭弹层也不释放，造成较大 `setData` 和长期视图驻留。
- 搜索确认和分页没有稳定查询键、完成结果复用及同页请求共享；晚返回主要依赖单一 serial，无法表达主查询与单页请求的不同边界。

`git log -S`/`git blame` 将相关行为定位到 `1de042b5` 和 `6b5b30fb`。

## 视觉与交互基准

当前 Web 通讯录 Storybook 的 390、320、科室、人员、筛选、搜索结果、空/错/加载和大字号状态是唯一主体黄金基准；用户附件只作交叉校对。沿用现有令牌：主色 `#0A66D5`、浅蓝 `#EAF3FF`、页面底 `#F4F7FB`、卡片白、主文字 `#16202A`、次文字 `#5E6A78`、边框 `#DCE3EB`。

主体顺序固定为模式切换、院区导览卡、搜索框、使用提示、状态/结果；不引入新的视觉体系。

## 状态边界

### 逻辑层

每种模式只保存当前会话需要的运行态：

- 原始 facets、固定七级筛选状态和 facets 加载状态；
- 原始聚合结果、当前主查询、分页游标、已追加页和进行中请求；
- 收藏数据、主列表滚动位置、弹层滚动位置及其 facets 版本；
- 请求代次、刷新代次和恢复弹层所需的最小元数据。

### 页面 data

页面 data 只保存当前 WXML 绘制和交互所需内容：当前模式、输入值、轻量导览摘要、状态、当前可见卡片、`hasMore`、交互禁用状态，以及唯一活动弹层。隐藏模式不长期保存完整卡片或筛选树；切回时从该模式原始结果投影当前视图。

原始接口条目只留在逻辑层，视图卡片只含 WXML 使用字段。不得在实例运行态和 data 中各存一份相同完整卡片数组，也不在两种模式同时保留视图卡片。

`syncFilterSections` 拆分为：

- `syncGuideStops`：只生成导览层级、标题和已选摘要；
- `buildActiveSheetSections`：只在打开弹层或弹层内选择变化时生成活动模式选项。

关闭弹层后清空选项和节点，只保存原始 facets、选择与滚动数值。

## 权限、上下文与版本

工作台向通讯录提供权限上下文是否就绪、真实群组角色、开发后台管理员标志、群组版本和上下文刷新序号。账号 ID 仍从登录会话读取，不经过 WXML。

稳定权限指纹只由真实 `role + isDeveloperAdmin` 按固定顺序生成。群组版本是额外的保守失效上下文，不被当作权限完整性的替代。未知权限上下文不得以空值或默认值复用旧结果；独立页仍可请求并由服务端鉴权，但禁用完成结果复用。

现有导入批次代表 facets 与条目的原子完整快照，但搜索响应不返回版本。因此只在当前页面会话、权限已知且重新观察到的 facets 批次未变化时复用完成结果。前台恢复、账号/群组/权限/群组版本变化和主动刷新都提升上下文代次并失效旧结果。

保留风险：facets 与搜索是两个 HTTP 请求，可能恰好跨越发布边界。本轮不擅自新增 API；采用会话内、权限已知、前台复核和主动刷新失效的保守规则。

客户端上下文只用于缓存隔离和失效，不作为安全凭据；服务端对每次请求继续最终鉴权。日志只记录脱敏哈希或计数，不输出完整账号、权限指纹、筛选值或游标。

## 查询键

使用稳定 JSON 元组序列化，不拼接字符串：

- `contextKey`：账号、群组、权限指纹、模式、已观察导入批次、群组版本；
- `baseQueryKey`：`contextKey`、trim 后搜索词、固定七级筛选状态、页大小，不含游标；
- `pageRequestKey`：`baseQueryKey` 加 `first-page` 或不透明游标。

固定筛选顺序为 `campusCode`、`section`、`building`、`floor`、`department`、`subunit`、`entryKind`。每级必须保留固定位置并区分 `unset`、`all`、`value`；即使前两者发送服务端时都省略字段，也不能生成相同键。

`baseQueryKey` 用于判断当前视图是否已是同一结果；`pageRequestKey` 用于进行中请求共享。分页追加仍属于同一 `baseQueryKey`。

## 请求与竞态

每种模式最多保存一个已完成主查询：

- 相同完成 `baseQueryKey` 再次确认直接无操作，包括已加载多页；
- 相同 `pageRequestKey` 共享同一 Promise，不同游标不互相复用；
- 新主查询重置逻辑分页，旧卡片只作“正在更新”快照并禁用拨号、收藏和翻页；
- 成功后一次替换；失败后清除快照并显示错误/重试；成功空结果可复用；
- 失败、中止、淘汰和上下文失效不得写入完成状态；
- `finally` 只释放自己的进行中记录；卸载后禁止 `setData`；
- 主动刷新/主动重试绕过完成复用，真实发起请求。

所有响应执行实例、上下文序号和查询键三重校验。分页追加还检查当前 `baseQueryKey`、对应 `pageRequestKey`、预期游标、该页未追加以及期间没有刷新/重新搜索。401/403 或账号、群组、权限变化立即清除双模式 facets、结果及过渡卡片。

## 异常与滚动

- facets 加载显示明确骨架；筛选按钮在视觉、无障碍和事件层都禁用。
- facets 失败按模式重试；纯关键词仍可搜索，但版本未知时不进入完成复用。
- 无有效筛选层级显示“当前无需筛选”，弹层绝不为空。
- 输入防抖 240ms，确认键立即执行；选择、清除和层级联动即时生效。
- 翻页失败保留已成功页和游标并提供当前页重试；无效游标提供“从头刷新”。
- 主列表与弹层滚动按模式保存；弹层滚动绑定 facets 批次。导览目标优先，普通打开才恢复旧位置。
- 选项 `setData` 完成且节点挂载后恢复并夹紧范围。滚动事件只写实例字段，不高频 `setData`。

## 性能和验收

修复前固定 fixture：初始 `setData` 10 次/13,386 B、最大 5,495 B；开弹层 5,560 B；关闭后驻留 72 个选项；重复确认新增 1 请求。

修复后硬门槛：初始总字节和最大单包都不高于旧版 70%，次数不增加，重复搜索/翻页请求为零。相同环境多次取中位数，允许 10% 测量波动但不得稳定退化。

自动验收覆盖查询键、请求共享/失效、双模式/跨权限、卸载、加载/错/空、非空弹层、关闭释放、滚动恢复、目标定位、过渡禁用和分页错误。运行 Mini 定向及全量测试、类型检查、生产构建、source/performance/package/determinism、CI dry-run、格式/lint 与核心冒烟。

Node/静态结果不能代替微信原生运行时。匹配构建的体验版在小米 14 实测前一律标记“待验证”；体验上传需另行取得当次批准，不提交审核或正式发布。
