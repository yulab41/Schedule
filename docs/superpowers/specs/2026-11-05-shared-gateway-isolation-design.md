# 共享入口与资源隔离

用户已授权持续实施、保留AI工具并完成生产发布及验证。

1. 先将已运行的AI工具入口引用纳入Nginx发布文件，建立内容可核对的桥接发布。后续隔离发布以该发布作为即时回退前驱，保护两个网站。
2. 再将AI站点配置并入版本化共享网关，独立server_name、请求/连接限额、超时与日志边界。保留现有路径、浏览器本机处理、扫描安全策略和已关闭的服务器媒体中转。
3. AI后端继续独立systemd服务。采用半个CPU核心上限、较低CPU/IO权重、192MiB软内存阈值、384MiB硬上限、64MiB交换及128任务上限。基线约12MiB内存/37MiB交换，部署前复核当前占用，避免将硬上限设在当前占用以下。
   预算作为独立的前向控制，应用回退时继续保护主机。每次设置前保存root专用的旧有效预算，设置失败自动恢复，预算自身出现问题可通过受锁的显式恢复命令恢复审计记录中的旧值。
4. 排班与AI业务代码、数据库及凭据各自管理，共享网关只承担路由。生产备份先于应用部署，重载后对两个域名、陌生Host、排班API与限额分别验证。
5. 以相同口径记录响应/资源基线与复测。小样本健康探测只验证可用性，历史排班慢请求归因继续区分证据，不填写未测性能提升。

验收包括发布文件与清单一致、两个网站关键页面可用、AI资源限额持久生效、受限负载时排班仍响应，以及本地/GitHub/服务器发布身份可追溯。应用源未改时复用已有应用证据，运行配置和发布路径的定向回归及生产验证。
