# 小程序下拉菜单滚动边界自适应实施计划

## 目标

在不改变选择值、业务事件和日期/月滚轮的前提下，让 selector 模式按工作流弹窗实际滚动可视边界
决定展开方向和最大高度，消除靠底部菜单被裁剪的问题。

## 步骤 1：建立红灯回归

- 在共享选择器控制器测试中加入“窗口下方充足、滚动边界下方不足”的案例。
- 在工作流选择器测试中覆盖同一边界输入。
- 增加模板契约测试，钉住换班、休假和值班滚动弹窗向 selector 传递边界。
- 在旧实现上运行目标测试并记录预期失败。

## 步骤 2：实现共享放置结果

- 抽取纯放置计算，输入触发器、窗口、期望高度和可选边界。
- 输出 `placement` 与 `maxHeight`；非法边界保持窗口回退。
- `scheduleSelectorPlacement` 只负责测量、关闭态保护和一次性写入结果。
- `ui-selector` 与 `ui-date-picker` 同步新增边界属性和最大高度数据。

## 步骤 3：接入工作流弹窗边界

- 为换班、休假和值班面板增加统一形状的 `{ top, bottom }` 状态。
- 表单显示完成后测量当前 `.workflow-sheet-scroll`；打开 picker 时刷新。
- 所有 selector 模式 picker 接收该边界；月份和日期模式不改变行为。
- 弹窗关闭时清理边界，避免复用旧窗口坐标。

## 步骤 4：样式与模板

- 选项层用计算结果设置动态 `max-height`，默认仍为 300px。
- 保留现有 up/down 类名、动画、选中态和关闭层。
- 测量完成前继续隐藏，避免方向闪烁。

## 步骤 5：验证与收口

- 目标测试转绿，并复跑现有 selector/workflow/p7 套件。
- 运行格式、lint、小程序 production build 和 Mini 验证。
- 用既有离线开发者工具复现场景验证：底部 picker 向上且选项可点击；顶部 picker 仍向下。
- 更新 `docs/project-status.md`，逐行审查 diff 后提交并按上游配置决定是否推送。
- 模拟器结论与小米 14 体验版验收分开报告。
