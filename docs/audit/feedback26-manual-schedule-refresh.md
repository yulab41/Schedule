# Feedback26 手动排班刷新与日期范围

## 范围与根因

- 顶部“编辑/预览/草稿/发布”原先主要切换本地状态；预览可复用旧模型，草稿与发布直接复用 `_history`，因此发布后再次切换可能看到旧数据。
- 草稿发布成功调用通用历史刷新；该函数按发布前的 `release` 状态返回草稿页，没有进入发布记录页。
- 编辑表单仅暴露开始日期，预览与草稿应用固定使用开始日起 30 天，用户不能选择更短的结束日期。
- 阶段切换与发布流程由 `591ccff6` 引入；本轮通过 `git log -S` 与 `git blame` 核对调用点后修改。

## 修复

- 四个阶段每次点击均执行对应读取：编辑重载页面配置，预览重新生成，草稿/发布重新读取发布历史。
- 草稿发布成功后刷新历史并进入“发布”阶段；失败或冲突仍留在当前操作上下文。
- 编辑表单按三行排列：模板+岗位、开始+结束、周期+人员。结束日期成为预览与草稿应用的真实 `endDate`。
- 后续确认将应用范围放宽到含首尾最长 366 天；模板周期仍为 1–30 天、最多20人和600个模板格。共享契约、领域生成、API校验与Mini校验使用独立的应用范围常量，服务端沿用既有按月份拆分草稿/发布周期的事务流程。
