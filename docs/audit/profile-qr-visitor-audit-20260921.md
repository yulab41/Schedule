# 个人联系方式、二维码与访客审计改造（2026-09-21）

## 结论与范围

阶段一代码已完成并通过本地自动化。用户在设计预览后撤回顶部导航改版，因此原生五个主页面和 Storybook 均恢复原有群组区、角色和“日历 / 通讯录 / 换班 / 我的 / 更多”页面标题；本批没有把 Storybook 或新 UI 库加入小程序运行包。用户随后认为二维码四字段偏大，最终采用原生 Canvas 40px（初稿 50px）和 Storybook 20px。

本轮没有生产授权，未执行生产备份、迁移、部署、提审或正式发布。新 Mini 依赖新 API，因此也没有上传一个注定无法在当前生产 API 上工作的体验版。开发者工具授权任务仍为 pending；没有模拟器扫码和小米 14 同构建证据。

## 实现结果

### 个人联系方式

- “我的”页始终显示“手机号（点击修改）”“短号（点击修改）”，整行可点击，分别打开单字段弹窗。
- 支持新增、修改、清空、取消、校验失败和 409 并发冲突后刷新。手机号仅本人修改；短号允许本人或任一所在群的群主/管理员修改，管理员界面明确提示会同步所有群组。
- 号码提升为账号级数据。任一号码变化会使相关群组联系方式确认失效；只有手机号变化撤销手机号公开同意。
- `0063_account_short_phone_visitor_context.sql` 按 `updated_at DESC, id ASC` 确定性选择最近旧短号并同步成员版本。旧成员短号列本阶段不删除，避免尚未切换的旧应用受损。

### 邀请与二维码

- Mini 运行时删除邀请生成、分享、撤销、接受邀请页面与路由；不再显示或输入群组码，相关界面统一使用“访客二维码”。
- 新成员绑定码与访客码接口只返回当前运行环境的一张图片。`release` 使用正式版，`trial` 使用体验版，`develop` 映射体验版；无法识别的环境失败关闭。
- 成员码只显示居中的“群组名、姓名、工号、有效期”四项；长群组名可换两行，二维码本体保持 640×640，画布 720×1240，字段 40px。
- 外部不再出现“正式版 / 体验版”标题。一次性二维码安全提醒保留并居中。
- 为保护当前正式版的严格契约，旧邀请服务、`invite_tokens`、群组码列/尝试表、旧双码接口和兼容字段仍在服务端保留。阶段二必须在新正式版发布稳定且旧接口调用归零后再删除；这不是“已清零运行时残留”的最终状态。

### 访客审计

- 新增严格 POST 月份读取，一次提交访客密钥、月份、可选 `wx.login` 临时代码和版本化客户端上下文，身份信息不放入 URL。
- 微信换码只取小程序范围 OpenID，不创建用户、成员关系或登录态，不记录临时代码，不返回 `session_key`。换码或 `wx.login` 失败时日历仍可读取。
- 白名单上下文包含实际可得的品牌、型号、系统、平台、CPU/ABI、内存/性能等级、微信版本、基础库、语言、主题、调试状态、小程序版本与环境、屏幕/窗口/安全区、字体和网络。未知字段拒绝，单字符串和总字节数受限。
- 审计记录保存 OpenID（界面标注“非微信号”）、完整 IP、完整请求 ID、访问时间/月及设备上下文；列表默认摘要、点击展开详情，并明确标注客户端上报可能被伪造。权限沿用 `viewVisitorAccessLogs`，保留期仍为 90 天。
- 隐私说明位于 `apps/miniprogram/docs/privacy/visitor-access-audit-disclosure.md`。基础信息不需要昵称/头像/手机号授权弹窗，但微信平台若要求首次隐私确认，仍遵循平台要求。

## 上线与清理门槛

1. 用户明确授权生产操作后，按现场 live release 重新取得回滚候选，创建并验证生产备份，再部署阶段一 API 与 schema 63。
2. 冻结干净候选，分配不可变体验版并上传；分别验证 release/trial/develop 映射、二维码可扫和访客降级路径。
3. 取得当前构建的小米 14 证据；模拟器、自动化、上传成功均不能替代真机结论。
4. 新正式版需另行取得提交审核与正式发布授权。稳定后确认旧邀请/双码接口调用归零。
5. 再取得生产破坏性迁移授权，删除旧服务、路由、契约、表/列/索引/尝试表及兼容字段，重新做包体与数据库不存在性审计，才可宣称“零运行时残留”。
