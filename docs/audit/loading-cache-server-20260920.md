换班/请假/加班仍需要实时校验状态、审批权限和冲突，不将业务写入结果改成离线缓存。既有工作流控制器按月份复用排班，通讯录按查询与游标合并请求，节假日按年份合并在途请求。本批保留这些有效机制。节假日版本变化只重取年份数据，不因此删除整窗排班。

## 推送与兜底设计

复用现有 API 新增 `GET /groups/:groupId/calendar-change-stream`，基于 HTTP 分块事件流。API 成功写请求完成后发送无业务内容的 `changed` 提示，失败/回滚不发送。群内改动只通知本组；账号号码跨组共享，联系方式写入通知所有活跃订阅重新检查各自版本。跨进程作业和遗漏通知由重连与低频校验覆盖。

- 仅工作台可见时持有一条连接；onHide/onUnload、账号或群组切换释放。合并同一时刻的变更校验，保持既有选择、定位、滑动与视觉行为。
- 接入和每次通知前执行现有群权限校验。心跳每 15 秒只写少量字节，不读数据库。110 秒主动结束连接以重新鉴权；每账号最多 2 条、全实例最多 200 条；慢消费者关闭，避免无界缓冲。
- 初连/重连的 `ready` 提示触发版本补查，补上订阅建立前发生变化的窗口。正常重连间隔 1 秒，故障退避上限 60 秒。
- 不支持分块 API 或旧服务器返回 404 时停止流式重试。最后一次提示后 120 秒仍无新提示则校验一次；进入后台后定时器停止，回前台立即走已有校验。
- 手机持久缓存按账号和群组隔离；只缓存原有已授权响应中的联系人。正常业务更新通过 ledger 使缓存失效；离线只读仍受 24 小时上限。明确失权不能以离线模式绕过。
- 不增加依赖、Redis、额外监听端口、后台服务或数据库表。2GB 机器先采用有界单 API 进程通知；日后多 API 实例再评估共享消息通道。

微信官方类型定义包含 `RequestTask.onChunkReceived`（2.20.1）及 `enableChunked`（2.20.2）：[微信官方 api-typings](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)。运行时同时检测分块及响应头能力，不只比较版本号。
