# Skyline 3.17.2：月历/日期分页改原生滚动（体验版 155）

日期：2026-09-17　作者：Codex　授权：用户当次报障 + 既有「可自行提交、放行、上传」授权

## 用户报告（均只在 3.17.2；3.17.3 正常）

1. 请假页年月日选择器：定位按钮落下的是**临近月**而不是当月，且**没有跳转动画**；要求是"跨多个月也只做一个月的跳转动画"。
2. 请假页选择器左右切换仍会**反跳**。
3. 首页月历定位按钮同样问题（临近月 + 无动画）。
4. 首页月历左右切换**无动画**、内容**不跟手**（手势滑动正常）。

同时用户确认：3.17.2 的滚轮"已经和 3.17.3 基本一样"，并且低速时末尾更顺滑——**这一条是优点，本轮不动**。

## 根因

两处的程序化切页都是"3 槽环形 `swiper` + 改 `current`"。3.17.2 无法动画化程序化跳转（并会反向重播圆形滑动），所以此前一轮把它设成 `duration: 0` 并手动补一次结算。后果正是本轮四条：**没有动画**（1、3、4）；而手动结算依赖"当前槽 == 目标槽"，一旦错过就丢结算 → 环形状态与画面错位 → **落到临近月 / 反跳**（1、2、3）。

## 实现（3.17.3 分支逐字未改）

按当轮确立的原则（最小改动优先；当低版本无法在原实现上适配时，为它设计匹配的实现而不是硬打补丁），把 **3.17.2 的分页换成原生横向 `scroll-view`** —— 与滚轮同一条已真机验证过的通道：

- 环形三面板、面板标记、插值/高度逻辑全部复用；面板体抽成 WXML `template`，swiper 分支与 scroll-view 分支**共用同一份面板标记**。
- `scroll-into-view` + `scroll-with-animation` 让平台自己动画**一个面板**；`bindscroll` 提供度量并驱动结算，手势滑动与程序化切换走**同一套结算代码**（所以跟手、反跳都消失）。
- 共享助手（度量合并、最近槽、面板 id、结算延时）放在 `calendar-period-pager.ts`，两个组件共用，不存在两套实现。
- 定位今天：先"无感归位"（同一月份内容，视觉无变化），再**单面板动画**滑到当月——跨多少个月都只滑一格。
- 3.17.3 仍走原 `swiper` 分支（`wx:else`），`swiperDuration`/`swiperCurrent` 行为与上一版相同。

## 追加：`.156` 的手势/方向问题与 `.157` 修复

用户回传：宽度已正常，但**手势左右滑动不能按月切换**，而是滑过 3 个月份的内容；定位按钮正常；左右按钮能跳月，但**动画方向相反**（3.17.3 正常）。

- **根因**：环形槽位会轮转，而原生滚动是按**物理位置**走的。`getAdjacentCalendarPeriodSlot` 会环绕（active=2 时"下一月"落到槽 0），于是"下一月"可能出现在左边 → 动画反向；同时一次手势可以拖过 3 个面板 → 看到 3 个月份内容。
- **修复**：兼容分支改为**物理顺序固定**——三块面板按 `relative` 固定为 `前 | 当前 | 后`（新增 `compatPanes`/`syncCompatPanes`、`syncCompatDatePanes`），滚动目标按 **月份方向** 取 `pane-0`（上）/`pane-2`（下）而不是槽位；每次结算后把内容轮转到中间并**无感归位**（`scroll-into-view` 到 `pane-1`、关闭动画、同步重置滚动度量）。于是：一次手势最多跨一个面板（= 一个月），方向永远与月份一致，环形槽位继续由宿主维护、互不干扰。

## 追加：`.157` 的闪烁/卡顿/快速手势阻塞与 `.158` 修复

用户回传：滑动卡顿；松手后**先闪一下滑动前的月份**再出现新月；高度自适应**要等闪烁结束才开始调**；快速连滑**被内容加载卡住**，必须等加载完才能再滑。

- **闪烁根因**：归位跳动原先写在结算里，会在**宿主持有的新面板渲染之前**先把滚动跳回中间面板——那一帧里中间面板还是旧月份，于是先闪旧月。改为**只在面板同步时归位**（`syncCompatPanes` / `syncCompatDatePanes` 在同一次 `setData` 里下发新面板 + 归位目标），两者同一渲染帧、不再出现旧帧；只有在"无步可提交 / 上一步仍在加载"时才单独归位（此时面板本来就该停留在当前月）。
- **卡顿根因**：拖拽过程中每个 `bindscroll` 都可能因槽位变化写 `viewportHeight`，等于逐帧 `setData`。改为**拖拽期间只记录状态，高度只在结算时设置一次**。
- **快速手势被阻塞**：上一步的月份数据还在加载时 `shiftPending` 会拒绝新的一步。现在把这次手势的**方向入队**（复用环形分页既有的有界队列），数据到达后自动接着走，并把滚动先归位，避免停在侧面板上。
- **验证（3.17.2 模拟器，连续取样）**：
  - 首页月历连续两次右滑再左滑：**2026-09 → 2026-10 → 2026-11 → 2026-10**，每次 `target=month-pane-1`、`compatPanes.relative=[-1,0,1]`。

## 追加：`.158` 的"出现别的月份单元格"闪烁与 `.159` 修复

用户澄清：切换后**短暂出现的是别的月份的单元格内容**（快速闪动），定位跳转也会闪。

- **定位到机制**：滚动跳转与内容更新在渲染器里不是同一帧，而提交那一下**可见面板本身也换了月份**（右侧"下一月"槽变成新的"下下月"），于是任一种先后顺序都会让某一帧看到错的月份。实测确认：提交后 `panes[2]` 被后续面板刷新改成了 2026-11（而用户正看着它）。
- **修法（保证不变量）**：提交时让**用户正看的那块面板与中间面板同月**（右滑→右侧与中间都是新当月；左滑→左侧与中间都是新当月），并在同一次 `setData` 之后归位；**干净的三面板映射只在归位真正落地后**（下一个滚动事件到达中间面板时）才替换，而那时被改动的面板已在屏外。这样任何一帧"可见面板"的月份都不会变。
- **验证（3.17.2 模拟器，取样）**：提交后 `panes = [2026-09, 2026-10, 2026-10]` → **中间与可见右侧同月**（`middleMatchesRight=true`）、`cleanupPending=true`；归位落地后 `panes = [2026-09, 2026-10, 2026-11]`、`cleanupDone=true`，月份 2026-10 ✓。
- **同时修**：手势开始就切换高度（实测 `viewportHeight` 在拖拽中即由 372 → 310，而不是等结算）；归位与新面板同一 `setData`；上一步未回时把方向入队。另给两个原生滚动容器加了 `bounces="{{false}}"`（无属性告警），用于压制惯性末端的内容拉伸。

## 追加：`.159` 的三项遗留与 `.160` 修复

用户回传（仅 3.17.2）：① 高度改变要等滑动动画归位后才开始，呈"两段式"（3.17.3 是同步的，滑动归位时高度也调好了）；② 按定位按钮后整页会上滑，月历与顶部导航的间隙变小（左右滑动与左右按钮不会，只此一处）；③ 切换月份仍不够流畅、略卡。

- **① 高度时序**。`setData` 探针取到：按钮/定位切月时**高度与滚动目标写在同一次 `setData`**（日志形如 `setVh{withPager:true}`）。平台会把已经在跑平滑滚动的节点上的高度过渡推迟到滚动结束，于是表现为"先滑动、后变高"。改为**高度单独先写一次**、滚动目标在下一次更新里设置。实测：`setVh vh=310`（t=17）→ `setPager{pane-2, animated:true}`（t=35）→ 首个滚动事件 t=84；DOM 高度过渡（240ms）完整落在滑动（≈280ms）之内。同时保留"一次步骤只写一次高度"的单写者约束（删掉结算期的二次写高度，`gridHeight` 观察器在步骤期间让位）。
- **② 定位位移**。DevTools 逐帧测量（模拟器 3.17.2）：定位后页面固定上移 14px——`#workbench-content-top` 由 `svTop+14` 变成与滚动容器顶端对齐；根因是 `scroll-into-view` 把**锚点顶端对齐到容器顶端**，而该锚点位于内容上内边距之下。**同一测量在基础库 3.17.3 上完全相同**（`anchorTop 125→111`、`svTop` 不变），因此这不是 3.17.2 独有差异，而是两个版本共用的缺陷。定位按钮本身就在月历卡片内（点击时月历必然可见），所以移除月/周定位后的页面滚动；列表视图仍保留 `list-day-<today>` 行定位。回归测试：`workbench-runtime.test.mjs` 新增"月/周定位不得设置页面滚动"与"列表定位仍设置行定位（不要过度修复）"两项。
- **③ 切月流畅**。程序化切月的耗时结构（探针）：按下 → 68~351ms 原生滚动（≈283ms）→ 之后固定等满 140ms 结算窗口 → t=511 才提交。程序化步骤本来就知道目标面板，于是新增共享常量 `CALENDAR_PERIOD_ARRIVAL_SETTLE_MS=48`：滚动到达目标面板后再等 48ms 即结算；手势仍保留 140ms（动量在慢帧上可能停顿，不能缩短）。实测提交 t=511→435。

### 卡死定因（模拟器探针，决定性）

1. `_compatCleanupPanes` 永久挂起 → `syncCompatPanes` 的 `cleanupPending` 分支一直跳过重定位；

### 3.17.3 为何能同步（分析）

3.17.2 兼容路径此前用的是 `scroll-into-view` + `scroll-with-animation`，即**一段原生平滑滚动**。模拟器里逐帧测不到延迟（下方内容在滑动期间就开始位移：661→649.4→602.5→599，说明本机不冻结布局），但真机证据连续两轮一致：高度/布局变化被压到滚动结束之后。因此不把这条当作"写入顺序"问题，而是**换掉动画通道**本身。

- 高度与位移**在同一次 `setData`** 下发，时长与缓动完全一致（240ms、`cubic-bezier(0.33, 1, 0.68, 1)`）→ 同帧起、同帧落；
- 提交时在**同一个更新**里换回干净环并把轨道归零（位移与面板内容同时变，可见面板的月份不变），因此程序化步骤不再需要"等滚动事件落位"的清理，也就没有可挂起的中间态；

- 滑动中途落指会先把轨道归零再交给手势，避免两个通道叠加。
