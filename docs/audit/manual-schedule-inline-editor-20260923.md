# 手动排班一次性编辑与模板删除交付记录

## 结论

本批把“模板定义”和“一次排班应用范围”拆开：模板只保存岗位、人员、周期与最多 600 格矩阵；页面当前编辑内容可以不保存模板，直接预览并创建草稿，应用日期含首尾最多 366 天。既有已发布模板预览/应用响应保持不变，新接口使用独立严格契约。

## 行为变化

- 模板/岗位首行采用约 2:1，日期、周期/人员继续 1:1。触发器与选项均单行省略；删除胶囊固定行尾。
- `canPreview` 只校验当前岗位、人员、周期、矩阵和日期。预览成功后保存不可变请求快照，生成草稿复用该快照；任何后续编辑都会使旧预览失效。
- 保存模板只创建/更新模板，并在成功后恢复服务端版本和干净状态；开始/结束日期保持用户当前选择。
- `POST /groups/:groupId/manual-schedules/preview` 与 `POST /groups/:groupId/manual-schedules/drafts` 接收编辑快照。草稿端点只创建草稿，按业务月拆分；幂等指纹包含完整快照和日期，事件类型为 `manual_schedule_inline_applied`。
- 已保存模板显示删除 action；action 不触发选择。确认后调用既有软删除接口，新建模板没有删除入口。

## 回归定位与语义审计

- `git log -S` / `git blame` 定位 `591ccff6` 引入保存前禁止预览及保存后重置应用日期；`d1e53646` 引入模板区等宽两列。
- 本轮不是语义等价重构：预览前置条件、草稿来源和日期范围均有明确变化，因此先写旧代码失败的新回归用例。
- 已发布模板旧端点与响应形状不加字段；新响应不含模板 ID/版本。模板写接口仅由显式“保存模板”触发。
