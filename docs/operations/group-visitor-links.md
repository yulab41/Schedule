# 群组互为访客

## 行为与权限

两个群可通过稳定 ID 建立双向关联。当前与未来的有效正式成员（群主、管理员、成员）
在群组列表中自动看到对方群，身份为访客。访问资格按每次请求的原群成员关系计算，
不创建个人访客成员，不触发通知，不把关联继续传递给第三个群。

原群成员离开、被移除、停用、资料删除或原群/目标群解散后，关联访问不再生效。
恢复原群有效成员资格后自动恢复。已独立加入对方群的身份优先保留。
原有直接群组的显示顺序保持不变，关联群按名称、ID 排序追加。

关联访客只能查看已发布和历史排班；联系方式、短号、草稿、成员目录和管理操作均不开放。
即使账号具有平台管理员标记，单靠关联也不能获得目标群管理权。
关联访客不能单独加入或退出，接口返回：
“此访问权限来自群组关联，随原群成员资格变更”。原有直接成员的加入、退出规则保留。

实现入口只扩展群组列表、目录关系与登录访客日历；不扩展通用成员授权，
不伪造 membership ID，不增加公共 HTTP 管理接口或客户端响应字段。
Web/小程序继续使用现有 `guest` 身份。原匿名访客码行为保留。

## 数据与迁移

`0057_group_visitor_links` 新增唯一的有序 ID 对、启用状态、创建/更新时间及版本。
禁止自关联、反向重复与无效群 ID。迁移不预置任何真实群关系，不改成员或排班数据。
群组正常回收时删除涉及任一端的关联；外键级联作为完整性保障。

新应用要求 schema 57。上线前按 ECS runbook 备份并验证实际备份文件。
旧应用 release 的兼容声明上限可能是 56，不能直接绕过兼容门禁回退应用。
本功能的首选回退是停用关联，保留迁移、成员与排班数据。

## 运维命令

执行位置为对应构建的仓库/服务器应用根目录；使用其已审核的 MYSQL 环境。
命令不安装依赖、不执行迁移；连接错误不输出原始数据库参数。
在 ECS 上通过当前 release 的 Node/API 运行环境执行同一入口，不使用本地数据库文件。

本地构建入口（生产环境变量由服务器安全注入，不复制本地 `.env`）：

```powershell
node --env-file=.env apps/api/dist/group-visitor-links.js inspect "头颈外科医生" "头颈外科护士"
node --env-file=.env apps/api/dist/group-visitor-links.js enable <群ID1> <群ID2> <预检版本> <操作人标识>
node --env-file=.env apps/api/dist/group-visitor-links.js disable <群ID1> <群ID2> <预检版本> <操作人标识>
```

先按准确群名预检。名字仅用于定位，必须分别唯一匹配；重名、不存在或已解散时停止。
预检输出 ID、名称、关联状态、版本和双向人数，不输出个人资料。
`formalMembers` 为有登录身份的有效正式成员数；`membersWithoutDirectAccess` 为其中没有目标群
直接成员身份的人数，是本关联覆盖的人数，不承诺排除其他独立关联带来的访问。

核对两群 ID 和人数后，用返回的版本启用（未配置为 0）。修改在事务内按群 ID 固定顺序加锁，
版本冲突要求重新预检；重复启用/停用相同状态不产生额外行或重复审计。
每次实际变化写入 `audit_logs`，记录操作人标识、目标 ID 与前后状态。
操作人标识是审计标签，不是账号令牌；命令执行权限由服务器运维访问控制负责。

启用后再次预检，并用两群各一个成员验证群组列表与访客日历。
确认成员人数、排班总量未因配置而变化。停用后验证关联访问撤销，独立身份仍保留。

## 本次配置边界

只启用经真实环境核对的头颈外科医生群与护士群。不按名称硬编码运行时权限，
不自动关联其他群，不上传新版小程序。生产备份、迁移、部署和启用按当次授权门禁执行。
