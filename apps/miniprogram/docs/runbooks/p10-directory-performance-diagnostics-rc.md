# 通讯录半屏筛选与性能诊断：小米 14 体验版步骤

只使用与本轮短 SHA、`trial`、Skyline、基础库、微信版本和构建时间一致的体验版。微信开发者工具只作辅助；未取得本清单的真实手机记录前，性能结论统一为“待小米 14 体验版实测”。

## 1. 先校准版本并开始记录

1. 打开体验版，进入“更多 → 测试工具”，截图顶部构建校准条和“手机与微信环境”。
2. 在“通讯录性能诊断”点“清空记录”，再点“开始记录”。
3. 点“回到工作台测试”，进入“通讯录”。不要复制或截图真实姓名、号码、工号或筛选值。

## 2. 半屏筛选

1. 分别在科室和人员模式打开筛选：顶边应在可用窗口中部附近，“完成”和“清除全部筛选”始终可见。
2. 只从顶部横条下滑一次并观察跟手/回弹/关闭；在列表内上下滑动时 Sheet 不得被拖动或关闭。
3. 滚到最后一个层级和最后一项，确认不被底部安全区遮住；关闭再打开，筛选状态和滚动位置仍在。
4. 条件允许时旋转横屏再回竖屏，重新打开筛选；高度应随当前窗口变化，列表仍可滚动。

## 3. 搜索性能标准场景

在人员模式依次执行：页面会话内第一次搜索、相同条件第二次、不同关键词、带筛选搜索；再切到科室模式执行一次搜索。每个主要场景尽量做 5 次。不要用无意义搜索反复冲击服务端，也不要预加载完整人员数据。

条件允许时，在 Wi-Fi 完成一组后切换移动网络再完成一组。若网络条件不允许，报告中写“未测试”，不要猜测。

## 4. 停止并复制

1. 回到“更多 → 测试工具 → 通讯录性能诊断”，点“停止记录”。
2. 截图最近记录的总耗时和阶段摘要。
3. 点“复制最近 10 次”，把完整文本发给 Codex；记录不足 10 次时会复制已有记录。
4. 若某次明显最慢，再点“复制最近一次”补充该条，并说明当时使用 Wi-Fi 或移动网络。

Codex 收到后先核对 SHA、trial、renderer、基础库、微信版本和构建时间，再按每个场景报告中位数、最慢一次与各阶段耗时。只有数据表明请求内占比最高时，才进入服务端分段计时或索引/部署影响评估。
