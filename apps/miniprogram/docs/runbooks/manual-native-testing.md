# 用户人工原生验收手册

## 决策与边界

P1 及后续阶段不使用 MiniTest/Minium 云测。原生验收由用户人工操作微信开发者工具 GUI 和实体 Android 完成；用户反馈“通过”即打开下一阶段。LLM 仍不得启动、唤醒、重启、控制或自动化本地微信开发者工具及其 CLI。

Storybook、静态构建和 `miniprogram-simulate` 负责开发期快速回归，但不能替代人工查看真实微信运行时。项目自有截图比较器保留为可选诊断工具，不是用户通过反馈的前置条件。

## Codex 交付前置条件

在请用户测试前，Codex 必须完成并报告：

1. staging/production `src → dist` 构建、类型检查、源码/产物边界、Worklet、包体和确定性门禁通过。
2. `miniprogram-simulate` 与相关组件/页面测试通过。
3. 当前待测 commit、四条测试路由和已知限制已写入 `docs/project-status.md`。
4. 不要求用户提供 AppSecret、上传私钥、token 或任何云测配置。

## 用户准备

1. 用户人工打开微信开发者工具 GUI。
2. 打开项目 `E:\AItools\Schedule\apps\miniprogram`；不要直接打开 `dist`，`project.config.json` 已把 `miniprogramRoot` 指向 `dist/`。
3. 用户点击“编译”。若 GUI 显示旧内容，先关闭项目后人工重新打开，再编译；不要让 LLM 操作 GUI/CLI。
4. 默认只需编译基础控件页，滚动到最下方“人工测试入口”，即可在模拟器和用户 Android 中依次进入月历、7×7 与 20×30。系统返回操作会回到入口。
5. 如果某个页面无法从入口打开，可用“添加编译模式”按下表直接打开该独立页面作诊断。

| 编译模式 | 页面路径                        | query          |
| -------- | ------------------------------- | -------------- |
| 基础控件 | `pages/index/index`             | 留空           |
| 月历     | `pages/calendar-poc/index`      | 留空           |
| 日常矩阵 | `pages/manual-matrix-poc/index` | `mode=daily`   |
| 最大矩阵 | `pages/manual-matrix-poc/index` | `mode=maximum` |

本轮都是确定性 PoC，不登录、不调用业务 API、不修改正式排班。

## P1 人工检查清单

### A. 基础控件

1. 页面整体与已确认的 Storybook 基线一致，没有 TDesign 默认外观或横向溢出；页面必须能从顶部连续滚动到最下方“状态反馈”卡片。
2. “发布排班 / 保存草稿 / 撤回发布 / 正在保存”四种按钮层级清楚；390px 宽度为两列且两列共同铺满内容区，320px 为单列满宽，加载按钮不可误触。
3. “微信值班提醒”由关闭切到开启，颜色、圆角、滑块位置和按压反馈自然；禁用开关不可切换。
4. 取消“已核对联系方式”，再选择“周视图”；checkbox/radio 状态只变化一次且点触不偏位。
5. 输入框可获得焦点、键盘不遮住当前字段，关闭键盘后页面可继续滚动。

### B. 动态月历

1. 初始 2026 年 10 月只显示 5 周共 35 格；切到 2026 年 11 月显示 6 周共 42 格，不得保留空白第六周或裁掉真实第六周。
2. 月历卡片与下方详情之间有明确 12px 间距；月历左右下角不再暴露灰色反圆角。
3. 点选当月最后一行左角或右角的可选日期时，蓝框跟随卡片底角弧度；详情日期、人员和班次同步，跨月灰色日期不可点选。
4. PC 模拟器和 Android 都能看到上一月、定位今天、下一月三个控件；按钮与完整左滑/右滑都只切一个月，不丢第一次手势。
5. 左右滑动及切换完成时不暴露反圆角、不残留旧高度；“定位今天”回到 2026-10-14。

### C. 7×7 日常矩阵

1. 显示 7 人×7 天；手指拖动及松手后的惯性滚动期间，日期表头与主体日期列属于同一个横向滚动面，应同帧、等速、同向移动并持续对齐，不再依靠另一张表头滚动容器追赶。
2. 本尺寸只需要横向滚动；人员行随矩阵壳层延展，页面整体负责纵向滚动；滑到右侧后进度提示更新。
3. 选择另一班种后点一个可用格，只更新该格并出现选中框；点击“撤销”恢复原值。
4. 滚动、点格和撤销均有即时反馈，没有持续卡顿或误触相邻格。

### D. 20×30 最大矩阵

1. 页面显示 20 人×30 天，初次可交互不超过约 2.5 秒，矩阵出现不超过约 1 秒。
2. 横向滑到中部/末端并覆盖松手后的惯性滚动；日期表头和主体日期列同一滚动上下文内移动，人员列横向冻结。随后用页面整体上下滚动检查 20 行，人员列与主体行持续对齐，左上角始终固定在矩阵壳层，不得有可感知延迟、黏滞、闪烁或错位。
3. 滚动过程中没有持续可感知卡顿；停止后可立即点格，反馈约 100ms 内出现。
4. “失效”成员/格不可修改；可用格可按当前班种更新，撤销只恢复最后一格。
5. 往返首尾后行列仍对齐，没有白屏、跳回顶部、丢格或异常重绘。

## 反馈格式与继续条件

- 全部通过：用户直接回复“P1 人工测试通过”或“通过”即可；不强制上传截图。Codex 将记录人工验收和设备信息（若用户提供），随后进入 P2。
- 发现问题：回复“页面 + 状态 + 现象”，例如“20×30，纵向滑到末端，人员列比主体慢半格”；截图可选但建议附上。Codex 只修复本轮失败项，重新交付同一检查清单，不提前进入 P2。
- 人工测试前静态门禁失败、页面无法编译或用户尚未反馈时，P1 状态只能是“已实现待人工原生复核”。
