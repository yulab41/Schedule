# P1 视觉确认说明

## 设计对象

- 对象：医院科室的排班工作台，不是通用管理后台。
- 使用者：需要在手机上快速查看、补录和发布排班的医护成员与管理员。
- 本轮唯一任务：确认原生小程序手绘组件应复刻的 Web 视觉语法；确认前不实现 WXML/WXSS。

## 视觉计划

### 色彩

全部来自 `@schedule/ui-tokens`，不新建小程序专属配色。

| 名称       | 色值      | 作用                   |
| ---------- | --------- | ---------------------- |
| 临床蓝     | `#0A66D5` | 主操作、选中和焦点     |
| 值班墨色   | `#16202A` | 标题与主要数据         |
| 病历纸白   | `#FFFFFF` | 卡片、表格和输入表面   |
| 工作台底色 | `#F4F7FB` | 页面画布               |
| 今日黄     | `#F5C518` | 只标记“今天”           |
| 周末红     | `#E03131` | 周末、节假日与风险提示 |

### 字体

- 标题、正文：当前 Web 的中文系统字体栈；为了微信/iOS/Android 的字形可校准性，不引入展示字体。
- 日期、时刻和矩阵数据：同一系统字体栈，启用等宽数字特性；数据对齐比装饰性更重要。
- 小标签：11–13px、较高字重，承载班种、节假日和状态，不作为装饰眉题。

### 布局

基础控件保持当前 Web 的紧凑密度：可见控件小，透明触控层不小于 44px。

```text
390 / 320
┌──────────────────────────┐
│ 页面标题        状态说明 │
├──────────────────────────┤
│ 主/次/危险操作           │
├──────────────────────────┤
│ 设置说明          52×30  │
│ 选择、输入、状态反馈     │
└──────────────────────────┘
```

日历只让 42 个日期格承担视觉重心，工具栏保持安静。

```text
┌──────────────────────────┐
│ 月份   上月  今天  下月  │
├──────────────────────────┤
│ 一 二 三 四 五 六 日     │
│ 42 格：人名/班次/变更    │
└──────────────────────────┘
```

矩阵保留真实的“人员 × 日期”结构，不把它美化成卡片列表。

```text
┌──────────┬───────────────┐
│ 值班人员 │ 日期/节假日   │
├──────────┼───────────────┤
│ 冻结姓名 │ 班次色块网格  │
└──────────┴───────────────┘
```

### 识别性元素

唯一强调点是“班次色块嵌入排班格网”：蓝色负责操作，班次自身颜色负责排班含义，今日黄和周末红各自只表达一种状态。开关固定为 Web 已确认的 `52×30px` 外观和 `60×44px` 触控层。

## 自我审查后的收敛

最初方案容易退化为常见的蓝色设置页。现收敛为：删除装饰性渐变、大号营销标题和无业务含义的编号；结构标签只说明“控件、月历、矩阵”的真实验收对象；视觉记忆点集中在医护排班格网和明确的状态编码。字体继续使用系统栈是 1:1 跨端校准要求，不作为可自由发挥的设计轴。

## 本轮状态矩阵

| 对象       | 必看状态                                            |
| ---------- | --------------------------------------------------- |
| 按钮       | 主、次、危险、禁用、加载                            |
| 开关       | 开、关、禁用；`52×30px` 可见尺寸与 `60×44px` 触控层 |
| 选择/输入  | checkbox、radio、输入、选择器、错误提示             |
| 月历       | 普通、今天、选中、周末、节假日、跨月、加班、换班    |
| 7×7 矩阵   | 日常密度、冻结表头/人员、节假日、单格选择与撤销     |
| 20×30 矩阵 | 600 个逻辑格、双轴滚动、冻结层、失效状态与撤销      |

本轮确认只锁定 Web 黄金基线。MiniTest 和真机结果要在原生 PoC 完成后另行确认。
