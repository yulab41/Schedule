# 视觉 1:1 验收标准

## 定义

- 功能、状态、权限和交互语义：100%。
- 稳定截图区域相似度：≥98%。
- 显著差异像素：≤2%。
- 关键布局几何偏差：≤2px。
- 动态原生区域只能使用版本化固定遮罩；不得临时扩大遮罩掩盖业务差异。
- 默认系统字号逐项对照；大字号可以重排，但不能截断、遮挡、失去焦点或无法滚动。
- 最终验收是逐页用户确认，自动指标不能代替人工判断。

MiniTest 官方差异用于真机截图和第一道门禁；98%/2%/2px 由项目自有比较器判定，因为官方 SSIM 门禁不能直接表达全部三项指标。

## 每页工作流

1. 使用 `frontend-design` 写明设计意图、视觉语言和状态矩阵。
2. 在 Web Storybook 生成 390×844 黄金图，并确认不是第三方组件默认外观。
3. 检查 320×844、大字号、键盘、焦点和减少动态。
4. 用户确认后才实现原生 WXML/WXSS。
5. 运行 simulate 状态/事件测试。
6. MiniTest 固定 Android/iOS 运行交互并截图。
7. 运行官方图片差异和项目 comparator，执行截图视觉批评。
8. 修正后由用户最终确认，并把证据写回黄金清单。

## 设计原则

- 视觉必须延续现有 Web 产品的医护排班语义、密度、颜色和层级，不以“小程序默认风格”替代。
- 基础触控区至少 44px；可见控件可以更紧凑，但点触面必须独立满足门槛。
- 令牌由 `@schedule/ui-tokens` 单源生成 CSS/WXSS；不人工维护两套颜色、间距、圆角和阴影。
- 原生 input/textarea/scroll-view/gesture 是能力原语，外观和状态由包装层控制。
