# ADR-0006：允许 Agent 操作微信开发者工具，编译/预览/上传不再逐次确认

- 状态：已接受
- 日期：2026-09-17
- 取代：[ADR-0002](ADR-0002-preview-without-local-devtools.md) 的执行边界部分

## 背景

ADR-0002 出于当时的环境风险，禁止 LLM 启动、唤醒、重启、控制或自动化本地微信开发者工具 GUI/CLI，
把全部原生验证交给用户人工操作。微信官方随后为开发者工具发布了可操作、可调试、可验证的
Skills 与 MCP 接入面（`wechatide` CLI、开发者工具 MCP、内置 skill 包），用户也在本机完成了安装
与登录，并明确要求 Agent 使用该执行面完成完整的小程序开发流程。

## 决策

1. 微信开发者工具是本仓库允许的 Agent 执行面。LLM 可以调用 `wechatide` CLI 与开发者工具 MCP，
   覆盖状态检查、登录、打开/关闭项目窗口、编译、构建 npm、模拟器、页面自动化、Console/Network、
   截图、推送预览/预览二维码和体验版上传。
2. 编译、预览和体验版上传不需要用户逐次确认。仍需用户当次明确批准的只有：提交审核、撤回审核、
   正式发布，以及删除云资源、生产数据库破坏性写入、真实支付等其他不可逆操作。
3. 发布身份要求不因执行面改变而放宽。体验版上传仍必须走 runbook 的版本分配、冻结干净候选、
   Manifest/receipt/tag 血缘与只追加 allowlist 流程，并额外记录上传路线（Node `miniprogram-ci`
   或开发者工具）。
4. 日常主循环仍不依赖开发者工具。Storybook、`miniprogram-simulate` 与 Node 静态门禁继续承担
   设计、状态与编译回归；开发者工具假死时不得阻塞 checkpoint，按 ADR-0002 的原有理由继续。
5. 证据分层不变。模拟器、页面自动化与截图属于开发期证据，不能冒充实体设备验收；小米 14 Android
   微信客户端体验版仍是最终视觉与交互验收来源。

## 理由与后果

开发者工具官方 Skill/MCP 提供了此前只能由用户人工完成的编译、模拟器、日志与截图能力，使 Agent
可以在同一条闭环里定位问题，而不必把每一步都交回用户。逐次确认会把这条闭环重新切碎，因此按用户
要求改为默认放行，只保留真正不可逆的对外动作作为人工门槛。

代价是 Agent 现在能够改变本机开发者工具状态并上传体验版。版本号一经上传即永久占用，因此上传路线、
版本与 Manifest 必须落盘可追溯；开发者工具与 `miniprogram-ci` 混用时的身份一致性由上传记录保证，
而不是由禁令保证。
