# Web 演进同步策略

## 目标

Web 在小程序迁移期间继续作为线上产品和视觉黄金源。每个 Mini 阶段都必须基于当时的 Web `main`，不能只复刻 2026-08-17 的静态快照。

## 分类规则

| Web 变化                                     | 处理方式                                                     | 示例                                                                   |
| -------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------- |
| 已在迁移计划中的功能发生修复、视觉或交互更新 | 对应 Mini 阶段实时吸收；已实现页面在下一 checkpoint 前补回归 | 月/周/列表日历、动态周数、连续周、触控状态、时间选择器、开关、手排矩阵 |
| 已在迁移计划中的公共契约/API 改变            | 立即评估阻塞性；共享契约和 Mini adapter 同 checkpoint 更新   | 登录、排班版本、导出、工作流、幂等                                     |
| 迁移计划批准后新加入的独立功能               | 登记 P10 parity backlog，最后实施，不打断 P1–P9 关键路径     | 院内通讯录                                                             |
| Web/PWA 专属能力                             | 记录为经批准的平台差异，不在 Mini 伪造等价物                 | service worker、浏览器安装提示                                         |

## 每阶段审计

1. 记录该阶段基线 Web commit。
2. 用 `git log <上一基线>..main -- apps/web packages/contracts packages/scheduling-domain packages/ui-tokens` 生成变更候选。
3. 将候选标为“实时跟随”“公共契约阻塞”“P10 backlog”或“平台差异”，写入阶段状态。
4. 实时跟随项先更新 Storybook 黄金、fixtures 和共享 presentation，再实现 WXML/WXSS。
5. 阶段 RC 再从基线到 `main` 复扫，未分类差异阻断发布。
